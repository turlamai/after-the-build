第四部 · 应用软件

窗口、按钮和输入框是怎样构成的

现在我们知道软件可以等待用户操作，并在事件发生时执行相应的函数。但用户看到的不是函数，而是文字、按钮和窗口。

为什么开发者通常不需要亲自计算每个按钮的每个像素？

从画面到可以交互的部件

屏幕上的图像可以由许多像素组成。一个像素可以具有由数字表示的颜色。程序通过系统提供的图形功能组织绘制工作，最终使屏幕显示对应画面。

但是，画出一个矩形并不意味着它已经成为按钮。按钮还需要知道自己的位置、是否可用、如何响应点击，以及应该显示什么文字。

把这些可复用的交互行为与显示能力组织在一起，就形成了控件（Widget 或 Control）。

窗口、文本输入框、复选框、列表和按钮都是常见的界面部件。它们构成了图形用户界面（Graphical User Interface，GUI）的基础。

为什么界面不只是一些固定坐标

假设报名窗口最初宽 600 个逻辑单位，姓名输入框宽 300。用户把窗口缩小后，如果所有部件都固定在原来的位置，有些内容就可能无法显示。

因此，界面通常需要规定各部件之间的空间关系，例如按钮排列方向、边距、最小宽度以及哪些区域可以随着窗口变化。

这类决定界面部件如何安排的机制称为布局（Layout）。布局可以利用控件的内容尺寸、父区域约束以及设计规则计算位置，不必为每一种窗口大小手工填写坐标。

系统还可能根据屏幕缩放比例将逻辑尺寸转换成实际像素尺寸，所以界面尺寸和物理像素数量不必相等。

从界面结构到屏幕上的像素

以一个包含标题、输入框和按钮的窗口为例。界面系统通常需要先建立这些部件之间的关系，再根据可用空间计算大小和位置。绘制阶段按照布局结果准备文字、颜色和图形，最终形成可以交给显示系统的画面。

这一将界面描述转换为可见图像的过程通常称为渲染（Rendering）。实际工具可能把布局、绘制与合成进一步拆分，也可能利用图形处理器（Graphics Processing Unit，GPU）加速部分工作。

对于输入，界面系统还需要根据鼠标位置等信息判断哪个部件应接收事件，这称为命中测试（Hit Testing）。键盘输入则通常交给具有输入焦点（Focus）的部件。一个按钮虽然被绘制出来，但若没有正确的事件目标及处理逻辑，仍然无法正常交互。

当窗口大小变化时，系统可能重新计算布局并重绘受影响的内容。若部件尺寸违反父区域约束，就可能出现截断、重叠等现象。解决这类问题应先检查布局规则，而不是盲目调整每个像素的位置。

界面显示的信息从哪里来

假设当前报名人数是 19，界面就应显示 19。成功报名后，人数变成 20，界面也应随之变化。

这里至少存在三件不同的事情：保存当前人数；按照报名规则决定新的人数；将当前人数显示给用户。

如果程序只把按钮旁边的文字改成 20，却没有更新真正用于计算的人数，下一次报名就可能继续使用 19。

因此，界面上的显示内容并不一定是应用真实数据的唯一来源。工程师需要明确哪份状态是权威数据，怎样把数据变化反映到界面。

有些工具允许开发者直接规定「按钮是否可用取决于剩余名额」这样的关系，这属于声明式界面（Declarative UI）的一种常见表达方式。另一些工具要求开发者在事件发生后主动调用更新操作。两种方式都需要正确管理状态。

原生界面和网页界面

桌面程序可以通过操作系统或图形工具提供的功能创建窗口与控件。浏览器也能显示文字、表单和按钮，并执行相应交互逻辑。

这两类软件的运行环境不同，但都需要处理输入、维护状态和显示输出。

原生应用（Native Application）通常指面向特定平台构建、利用该平台执行环境和能力的应用。这个词在不同产品语境中可能有更窄的含义，例如是否使用系统原生控件。

网页应用的具体工作方式，要等我们学习网络与浏览器之后才能完整解释。现在先理解：看起来相似的界面，背后的运行机制不一定相同。
