第三部 · 安全与工程判断

第 19 章 信息安全：威胁模型、身份与访问控制

安全是系统必须满足的设计约束，而不是功能开发完成后才考虑的附加选项。

一、安全目标与威胁模型

信息安全通常关注机密性（Confidentiality）、完整性（Integrity）和可用性（Availability），合称 CIA 三要素。机密性限制未经授权的读取，完整性保护数据和行为不被非法修改，可用性要求授权用户能够获得预期服务。

资产（Asset）包括数据、凭据、计算资源及业务能力。威胁（Threat）是可能造成损害的因素，漏洞（Vulnerability）是可被利用的弱点，风险（Risk）则需要结合发生可能性与影响评估。

威胁建模（Threat Modeling）首先识别资产、数据流、信任边界和可能的攻击路径，再决定安全措施。例如报名系统中，公开表单、管理员接口、数据库和第三方邮件服务属于不同的信任边界。本地应用同样面临恶意依赖、文件访问和不可信输入等风险。

二、认证与授权

认证（Authentication）用于验证主体身份；授权（Authorization）决定已识别主体是否允许执行特定操作。登录成功并不意味着可以读取所有记录。

会话（Session）用于关联多个请求的身份状态。服务端可以保存会话状态，并向浏览器发放会话标识；也可以采用其他令牌机制。无论采用什么方式，都需要验证有效期、撤销策略和权限。

基于角色的访问控制（Role-Based Access Control，RBAC）通过角色分配权限。基于属性的访问控制（Attribute-Based Access Control，ABAC）根据主体、资源、操作及环境属性决定访问。对象级访问检查还应验证用户是否有权操作具体记录。

仅隐藏管理页面的按钮并不能实现授权。客户端提交的用户标识和角色不应被服务器直接视为可信授权依据。

三、常见应用漏洞

概念 机制 防御思路
SQL 注入（SQL Injection） 不可信输入被解释为 SQL 语句的一部分 参数化查询
跨站脚本（XSS） 不可信内容进入可执行的浏览器上下文 上下文相关的输出编码、适当的 CSP
跨站请求伪造（CSRF） 浏览器在非预期请求中携带用户凭据 CSRF 防护、合理的 Cookie 策略
访问控制失效（Broken Access Control） 服务端未正确执行权限规则 服务端逐请求、逐对象授权
供应链风险（Supply Chain Risk） 不可信依赖或构建过程影响产物 依赖审查、锁定版本、受控构建

输入验证（Input Validation）用于检查数据类型、长度和业务约束，但不能单独代替参数化查询、输出编码或权限检查。

四、纵深防御与身份保护

纵深防御（Defense in Depth）通过多层控制降低单点失效的影响。例如网络访问限制、服务端认证、对象授权、数据库最小权限和审计日志应分别发挥作用。

多因素认证（Multi-factor Authentication，MFA）要求使用不同类别的认证因素。一次性验证码可以降低部分密码泄露风险，但仍可能受到钓鱼攻击。采用 WebAuthn 的通行密钥（Passkey）可提供更强的抗钓鱼能力，实际安全性还取决于设备、账户恢复及实现方式。

安全更新、唯一密码和凭据轮换属于持续维护工作，而不是一次性设置。

五、实践：验证自己的测试系统

在独立测试环境创建两个普通用户和一个管理员。明确访问矩阵：用户只能查看自己的报名记录，管理员可以查看被授权的活动记录，未登录用户不能读取私人资料。

通过现有测试接口验证允许和拒绝的场景，并检查服务端返回值及数据库是否发生意外修改。只测试自己拥有或获得明确授权的系统，使用虚构数据，不对外部系统开展未经授权的测试。
