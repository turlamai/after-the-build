第二部 · 计算机内部

存储器怎么知道我们要读取哪个数字

假设一个存储器保存四个字节：5、8、12 和 20。它保存的不只是一个值。我们想读取其中的 12 时，必须告诉它究竟要访问哪个位置。

给每个可访问的位置编号

最直观的方法是给这些位置依次编号：

位置编号 当前数据
0 5
1 8
2 12
3 20

这些用于定位存储位置的编号叫地址（Address）。地址 2 与数据 12 是不同的东西：前者指定在哪里访问，后者是那里当前保存的内容。

写入新的值之后，位置编号通常不变。例如向地址 2 写入 99，再读取地址 2，就会得到 99。

这里假设每个地址对应一个字节。这叫按字节寻址（Byte Addressing）。许多现代通用处理器使用这种方式，但并不是所有硬件的地址单位都相同。

地址也是二进制数据

四个位置只需要两个地址位，因为两个比特可以区分四种组合。00 指定位置 0，01 指定位置 1，10 指定位置 2，11 指定位置 3。

如果具有 n 个地址位，理论上可以区分 2 的 n 次方个地址。实际能够访问的空间还取决于硬件实现、地址分配以及系统配置。地址位数不等于真实安装的存储容量。

怎样进行读写

一种简化的存储器接口包括地址、数据和读写控制信号。

读取时，访问者提供地址，并发出读取要求。存储器选中对应位置，再返回其中的数据。写入时，访问者提供地址和新的数据，并在规定的控制条件下要求存储器保存该值。

真实硬件可能通过多个步骤传输地址和数据，也可能一次读写多个字节。不同存储器有各自的接口协议。本章只建立「选择位置、传递数据、控制操作」的基本模型。

一组承担部件之间数据或控制信息传输的连接，可以称为总线（Bus）。后文会再次遇到这个词。它不是一根必然同时承担所有工作的线，现代计算机可能使用复杂的互连结构。

地址怎样选择一个实际存储单元

以四个可以分别保存一个字节的位置为例。设地址的高位为 A1，低位为 A0。可以根据两个地址位产生四条选择信号：

A1 A0 被选中的位置
0 0 0
0 1 1
1 0 2
1 1 3

地址译码器（Address Decoder）把这些二进制输入转换为对应位置的选择信号。例如位置 2 的选择条件为 A1 AND NOT A0。

读取时，可以利用多路选择器，从四组保存值中选出目标数据。写入时，只有同时满足地址选择和写入使能的位置才应更新。

实际大容量存储器不会简单地为每个字节配置一个独立的大型选择器。它们会采用分层译码、存储阵列、行列选择以及其他技术。这里的模型解释的是地址位如何最终参与硬件选择。

一个数需要多个字节怎么办

我们在第一部已经知道，一个字节表示无符号整数时只能达到 255。较大的数需要多个字节。

例如 16 位整数 0x1234，可以分成 0x12 和 0x34 两个字节，分别保存在两个相邻地址中。

如果规定低地址保存 0x34，高地址保存 0x12，这叫小端序（Little Endian）；反过来则叫大端序（Big Endian）。

两种方式都可以完整保存这个数。问题在于读写双方必须采用一致的约定，否则读取时可能把 0x1234 误解释成 0x3412。

以后我们研究文件格式和通信数据时，仍然会遇到这样的规则。

地址并不总是直接指向一块物理内存

现在我们讨论的是一个简化的、直接访问存储位置的模型。现代计算机中的程序通常使用由系统管理的地址，这些地址经过转换后才对应实际硬件资源。我们将在操作系统部分建立虚拟内存的知识后再回到这个问题。

现在不必提前理解地址转换。我们只需要知道：计算机有能够保存数据的部件，而且能够根据指定的位置读取或修改数据。

如果我们把一组操作要求也保存到存储器中，硬件能否按照这些要求自动完成连续计算？这就是下一章要解决的问题。
