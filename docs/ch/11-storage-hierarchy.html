第二部 · 计算机内部

为什么计算机同时需要内存和硬盘

购买电脑时，经常会看到这样的配置：16 GB 内存、512 GB 固态硬盘。

如果我们只是想保存数据，为什么不把它们全部做成同一种部件？为什么内存通常容量较小，而硬盘容量更大？

保存数据的方式不只有一种

前面学习寄存器时，我们认识了能够保存状态的电路。某些存储方式可以非常快地读取和修改数据，但需要持续供电，一旦断电，保存的状态就可能消失。

具有这种特性的存储通常称为易失性存储（Volatile Storage）。现代通用电脑的主内存通常使用易失性的 DRAM。

另一些存储技术能够在断电后保留数据，称为非易失性存储（Non-volatile Storage）。固态硬盘（Solid-state Drive，SSD）通常利用闪存保存数据；机械硬盘（Hard Disk Drive，HDD）利用磁性介质保存数据。

不同技术在容量、访问延迟、读写方式、耐久性和成本上各有取舍。不是所有非易失性存储都具有相同速度，也不是所有易失性存储都可以直接互换。

程序运行时为什么需要内存

当我们关闭计算机时，一个已经安装的程序通常仍然保存在固态硬盘等持久化设备上。

启动程序后，计算机需要能够快速访问它的指令和正在使用的数据。通常，操作系统会将所需的内容放入或映射到可访问的内存中，并在需要时从持久化设备读取。

因此，不能认为安装一个 2 GB 的程序就必然占用 2 GB 内存，也不能认为关闭程序之后硬盘上的安装文件会消失。

具体的加载和地址转换机制，我们会在学习操作系统时解释。现在先区分保存长期数据的设备和支持程序当前运行的内存。

为什么在 CPU 和内存之间还有缓存

假设处理器反复对同一个数组中的数据进行计算。每次都从主内存取得数据，可能需要等待较长时间。

如果把近期使用过的数据的副本保存在访问更快、但容量更小的存储部件中，下次需要同样的数据时，就可能避免一次较慢的访问。

这种用于加快访问的存储叫缓存（Cache）。

当需要的数据已经在缓存中时，称为缓存命中（Cache Hit）；否则称为缓存未命中（Cache Miss），通常需要从更低层取得相应内容。

程序经常重复访问近期使用过的位置，或者访问相邻位置。这些行为分别称为时间局部性和空间局部性。缓存的设计利用了这些常见现象。

图中缓存与主内存之间的关系表示典型的数据访问路径；持久化设备则通过系统管理的输入输出路径访问。SSD 不是 CPU 普通缓存的下一级硬件缓存。

缓存怎样知道里面保存的是哪一份数据

缓存不能只保存数据值，还要知道它对应哪个存储地址。常见缓存按连续地址的一小组字节作为管理单位，称为缓存行（Cache Line）。

设一个虚构缓存只有两行，每行四字节。我们把内存划分为块：地址 0 到 3 是块 0，地址 4 到 7 是块 1，地址 8 到 11 是块 2。规定偶数块放缓存第 0 行，奇数块放第 1 行。

访问地址 所属块 缓存行 结果
0 0 0 未命中，取得块 0
1 0 0 命中
4 1 1 未命中，取得块 1
8 2 0 未命中，替换块 0
0 0 0 未命中，因为块 0 已被替换

行中保存的标记（Tag）用于区分映射到同一行的不同内存块，还需要有效性信息判断该行是否保存有效数据。这个教学例子采用直接映射（Direct Mapping），实际 CPU 常使用更灵活的组相联等结构。

缓存还要处理修改数据后怎样更新主内存，以及多个核心访问共享数据时怎样维护一致性。这些是现代计算机的重要问题，不能把缓存理解成一份永远不会过期的简单副本。

用访问时间理解缓存的价值

假设缓存命中需要 2 纳秒，未命中时在检查缓存之后还要额外等待 100 纳秒。若 100 次访问中有 95 次命中，那么总时间为 100 × 2 + 5 × 100 = 700 纳秒，平均每次 7 纳秒。

这组数字仅用于说明计算，不是具体 CPU 的实测性能。

由此可以理解，影响性能的不只有缓存容量，还有访问模式、命中率、未命中代价等条件。访问相邻数据有时比在很大的地址范围内随机访问更快。

内存不足和硬盘空间不足是不同的问题

如果一个应用需要大量工作内存，可能出现内存压力，即使固态硬盘上还有充足空间。

反之，如果电脑还有很多空闲内存，但持久化设备已经没有可用空间，应用仍然可能无法保存新的文件。

操作系统可以使用一些持久化空间辅助管理内存，但这不是把硬盘变成同样速度的 RAM。内存和持久化容量不能只因为单位都是 GB 就混为一谈。

你可以打开自己电脑的资源监视工具：Windows 上的任务管理器，或 macOS 上的活动监视器。观察启动一个常用应用前后内存使用情况，再查看磁盘容量。这是两个不同的指标。系统可能主动使用空闲内存缓存数据，因此也不要把单纯的高使用率直接当成故障。
