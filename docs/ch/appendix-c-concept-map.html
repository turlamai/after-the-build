附录 C 全书知识体系与学习路线

章节不是互不相关的常识集合，而是从计算机执行机制延伸到软件工程及 AI 协作的知识体系。

一、知识依赖

学习层次 主要章节 能力目标
计算机与软件基础 第 1—5 章 理解运行平台、硬件、文件、Shell、语言与运行时
计算机制与数据 第 6—8 章 理解算法、进程、内存、数据表示和格式
网络与基础设施 第 9—10 章 解释请求路径、协议分层、虚拟化及云服务模型
AI 系统与工程协作 第 11—12 章 区分模型、上下文、检索、工具及任务规格
工程实践 第 13—18 章 构建、部署、测试、凭据、成本、数据库与版本管理
安全与工程治理 第 19—23 章 威胁建模、密码学、隐私、架构决策及可靠性
综合验证 第 24 章及附录 独立解释、执行、核验与交付

二、从实际系统追溯原理

以活动报名应用为例，浏览器中的前端通过 HTTP API 调用后端（第 1、9 章）。后端由操作系统中的进程执行（第 2、5、7 章），解析 JSON 数据（第 8 章），验证权限和输入（第 19、21 章），通过数据库事务保存报名记录（第 17 章）。

应用版本通过 Git 管理（第 18 章），经 CI 构建、测试及部署（第 13、14 章），在云资源上运行并产生费用（第 10、16 章）。凭据与密码学机制保护必要的访问及通信（第 15、20 章），监控和恢复方案保障持续服务（第 23 章）。

AI Agent 可以协助设计、实现及检查上述环节（第 11、12 章），但技术选型和高风险决策仍需要依据需求、证据和责任边界（第 22 章）。

三、按问题定位知识

问题 建议阅读
程序无法在另一台电脑运行 第 1、2、5、7、18 章
页面访问失败 第 9、10、13、14 章
数据乱码或丢失 第 3、8、17 章
应用性能下降 第 2、6、7、14、16 章
Agent 引入错误修改 第 11、12、14、18 章
用户越权或凭据泄露 第 15、19、20、21 章
系统需要迁移或停止服务 第 17、18、22、23 章

四、学习与验证

初学者建议顺序阅读，遇到陌生术语先查附录 A，再回到工作原理。已有技术经验的读者可以按领域选择章节，通过知识检验识别盲区。

每学习一个技术概念，应尝试解释其定义、作用、适用边界和可观察证据。完成后使用第 24 章的五十问及附录 B 的任务模板，对同一个测试项目开展综合验证。知识能够迁移到新的系统与故障场景，才说明理解了机制，而不是只记住操作步骤。
