第一部 · 信息与计算

信息为什么需要一种表示方式

如果你问朋友今天是否下雨，他可以回答「下雨了」，也可以回答「没有下雨」。两种回答都很容易理解。但如果你希望把答案记录在一张纸上，并约定只允许写一个数字，应该怎么做？

我们可以约定：写 0 代表没有下雨，写 1 代表下雨。

这个办法很简单，却包含了计算机处理信息时最重要的思想之一：我们可以使用一组符号，按照事先确定的规则，表示另一件事情。

数字符号不自带我们赋予它的含义

假设另一张纸上同样写着 1，记录的却是房间里的灯是否打开。如果约定 1 表示灯打开，它就不是在描述天气。

纸上的符号没有发生任何变化，变化的是我们解释符号的规则。

信息（Information）在这里指我们希望表达的内容，例如今天有没有下雨、灯是否打开、某个人叫什么名字。数据（Data）是按照某种规则记录下来的表示。数据需要结合其解释规则才能还原我们关心的信息。

把信息转换成某种可以记录、传递和处理的表示，这个过程称为编码（Encoding）。根据约定从表示恢复其含义，则叫解码（Decoding）。

我们可以亲自制定一种编码：

实际状态 记录的符号
没有下雨 0
下雨 1

只要发送方和接收方都知道这个约定，接收方就可以根据 0 或 1 知道天气状态。假如接收方采用相反的约定，即使符号被准确传递，也会得出错误结论。

为什么只使用两种符号也可以表达复杂的信息

现在有三个问题：今天是否下雨、是否刮风、是否需要开灯。每个问题都只有两个答案，我们可以分别记录一个 0 或 1。

为了不混淆答案，必须规定顺序：

位置 所记录的问题
第一位 是否下雨
第二位 是否刮风
第三位 是否需要开灯

记录 101，就意味着下雨、不刮风、需要开灯。它在这里并不表示数字一百零一。

每增加一个位置，记录就能多区分一倍的可能情况。两个位置有 00、01、10、11 四种组合；三个位置有八种组合。

能够区分两种可能状态的一个二进制位置，称为比特（Bit），也称二进制位。在这里，我们先把它理解为一个可以取 0 或 1 的位置，不必马上研究它在硬件里如何保存。

并不是所有信息天然只有两种状态。如果天气分为晴、阴、雨三种，我们可以用两个位置表示，规定 00 为晴、01 为阴、10 为雨，11 暂时不用。两种符号经过组合，已经能够表示超过两种状态。

约定也是技术的一部分

上面的编码是我们自己制定的。它只要被使用它的人理解，就是有效的。但如果许多人分别制定自己的规则，他们之间交换信息时就容易产生误解。

因此，计算机领域存在许多公开的编码标准。我们会在后面学习其中一些，知道数字、文字乃至图像如何变成可由计算机处理的数据。

请先记住这里建立的两个事实：0 和 1 本身不意味着某个固定的现实事物；一组 0 和 1 的含义，需要由它所采用的表示规则来确定。

接下来，我们不再让这些符号代表天气，而让它们代表数字。我们将由此理解二进制。
