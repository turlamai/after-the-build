第五部 · 网络与 Web

一台计算机怎样同时运行多个网络服务

假设同一台电脑既提供报名服务，又提供文件查询服务。两种服务都使用同一个 IP 地址。

IP 地址可以帮助数据到达这台设备，但还需要区分应当由哪个通信端点处理数据。

端口是传输层的编号

TCP 和 UDP 都使用 16 位端口号（Port Number）。端口号的数值范围为 0 到 65535，其中某些值具有特殊用途。

例如，一个本机测试用的报名服务可以选择 TCP 8080 作为监听端口，另一个服务可以选择 TCP 8081。

端口不是机箱上的物理接口，也不是某一块固定的内存。它是传输层用于标识通信端点的数字字段。

TCP 与 UDP 的端口空间分别管理。一个 TCP 端口与相同数字的 UDP 端口不必表示同一个服务。

程序怎样使用网络

第三部已经学习过系统调用。应用通常通过操作系统提供的网络接口请求通信。

套接字（Socket）是应用进行网络通信时常用的一种接口和系统资源抽象。程序可以创建套接字，配置它，并通过相应操作发送和接收数据。

对于常见 TCP 服务端，程序会绑定（Bind）本地地址及端口，进入监听（Listen）状态，并接受（Accept）客户端发起的连接。

客户端（Client）是主动请求某项服务的一方，服务端（Server）是提供相应服务的一方。这是通信中的角色，而不是计算机硬件种类。

一个监听端口为何能处理许多客户端

假设两位申请者同时连接报名服务的 TCP 8080 端口。他们不必要求服务端为每个人额外公开一个监听端口。

一条 TCP 连接可通过本地 IP、本地端口、远端 IP 和远端端口等信息，在相应协议环境中区分。

客户端通常由系统选择一个适合的临时端口。服务端接受连接后，可以通过不同的已连接套接字分别与客户端交换数据。

实际套接字绑定、地址复用以及网络隔离机制会影响端口使用规则，因此不能简单认为全系统一个数字端口只能被一个程序使用。

为什么服务启动后仍然不能访问

程序可能没有成功监听，可能只监听本机地址，可能因防火墙规则拒绝通信，或者客户端根本没有到达正确设备。

向 AI 报告问题时，可以先提供服务绑定的地址、端口、使用的协议、客户端所在位置及实际错误，而不是仅说「网络不通」。
