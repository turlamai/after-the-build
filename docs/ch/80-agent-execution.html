第十部 · AI 与 Agent

Agent 怎样完成一项包含多个步骤的任务

假设我们给 AI 一项开发任务：增加取消报名功能，同时保证原有报名规则不会被破坏。

仅生成一段代码还不足以完成任务。系统可能需要读取现有项目、理解要求、修改代码、运行测试，并根据失败结果继续修正。

我们现在拥有理解这一过程所需的基础：模型可以生成下一步请求，应用可以调用工具，工具可以返回真实运行信息。

Agent 的核心是受控的执行过程

在本文语境中，Agent 指利用模型参与决策，并能够借助工具与环境交互、推进任务的软件系统。

模型可以根据当前任务和已知结果提出下一步。宿主负责组织执行过程、管理工具、提供上下文以及实施权限限制。

一次工作过程可能包括：

  1. 检查项目当前状态。
  2. 确定需要修改的代码和测试。
  3. 在获授权的范围内执行修改。
  4. 运行测试并读取结果。
  5. 根据证据决定是否继续修正或结束。

这是一种常见机制示意，不表示所有 Agent 都采用相同规划算法或具有无限自主能力。

为什么运行环境如此重要

如果 Agent 只能访问聊天内容，它就无法通过读取工具核对仓库实际文件。如果它具有仓库访问工具，也不代表能够在开发机器上运行构建命令。

Agent 的执行能力取决于宿主能够提供的工具和相应权限。

工作区（Workspace）可以是一个允许处理项目文件的目录或环境。沙箱（Sandbox）是一类用于限制程序资源访问及操作影响范围的机制。具体隔离能力取决于实现，不能仅凭名称保证安全。

例如，可以允许 Agent 在测试分支修改代码和执行测试，却不给它生产数据库访问凭据。

任务状态需要由应用管理

一个较长的任务可能需要记录已经检查的文件、完成的步骤、遇到的错误以及未完成的条件。

这些信息可以由宿主保存在结构化状态或任务记录中，在后续执行过程中提供给模型。

对话里出现「已经完成」的句子不等于项目状态已经更新。真正完成应当依据实际文件、提交、运行结果以及验收要求判断。

计划、执行和验证需要分别记录

对于增加取消报名的任务，Agent 可以维护结构化工作状态，例如需求是否明确、目标文件是否读取、变更是否写入、测试是否执行、是否满足合并条件。

这些状态不能仅由模型自己宣布。读取文件应以工具结果为依据；修改应能通过文件差异验证；测试应关联实际运行结果。

如果测试失败，可以回到分析和修改阶段；如果工具没有所需权限，应停止相关操作并说明阻碍，而不是声称已经完成。

持续任务也需要明确保存位置与恢复机制。一次模型调用结束，不意味着任务会自动在后台继续运行。只有宿主确实提供并启用了持续执行能力，才可以依照其实际机制推进任务。

为什么 Agent 也需要停止条件

如果测试始终失败，系统不能无限制地消耗计算资源或不断尝试高风险操作。

应规定允许的操作范围、任务完成条件、资源预算和遇到阻碍时的处理方式。涉及正式发布、真实用户数据或其他高影响动作时，需要相应授权与检查。

Agent 的价值不在于绕开软件工程，而在于将原本需要人工组织的部分工作连接成能够观察和验证的执行流程。
