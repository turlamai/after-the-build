第一部 · 计算机技术基础

第 8 章 数据表示、编码与文件格式

同一组字节需要在正确的编码、格式和数据模型下解释。

一、编码与格式

编码（Encoding）定义信息如何转换为可存储或传输的表示。文件格式（File Format）规定文件内容的结构。两者属于不同层次：一个 JSON 文件具有 JSON 结构，并可以采用 UTF-8 字符编码。

Unicode 为字符定义码点（Code Point），UTF-8 则规定如何将 Unicode 标量值编码为字节序列。例如字符 中 的码点为 U+4E2D，UTF-8 表示为 E4 B8 AD 三个字节。字符数不必等于字节数，也不必等于屏幕上可见的字形数量。

ASCII 的常见字符在 UTF-8 中保留相同的单字节表示。旧系统可能使用 GBK 等其他编码。用错误编码解码字节可能出现乱码或替换字符；如果错误结果再次保存，原始信息可能丢失。

二、整数、浮点数和字节序

整数与浮点数是不同的数据表示。浮点数使用有限精度，某些十进制小数无法精确表示。因此，财务应用通常应使用适当的十进制定点表示或整数最小货币单位，并明确舍入规则。

字节序（Byte Order 或 Endianness）描述多字节数值的字节排列。例如 16 位整数 0x1234 在大端表示中为 12 34，在小端表示中为 34 12。二进制协议需要明确字节序及字段长度。

三、结构化数据与序列化

序列化（Serialization）将内存中的数据结构转换为可保存或传输的表示；反序列化（Deserialization）执行相反过程。

CSV（Comma-separated Values）常用于表格数据：

id,name,quantity
001,Alice,3
002,Bob,0

CSV 缺少统一的强类型机制，编号 001 可能被表格软件自动转换为数字 1。引号、分隔符、换行和编码也需要明确。

JSON（JavaScript Object Notation）可以表示对象、数组、字符串、数字、布尔值及 null：

{"id":"001","name":"Alice","quantity":3}

JSON Schema 等机制可以约束字段类型、必填项和取值范围。格式合法不代表数据符合业务要求。字段缺失、null、空字符串和数字 0 应明确区分。

四、图像与压缩

位图（Raster Image）以像素采样表示图像；矢量图（Vector Graphic）使用几何形状等描述内容。SVG 是一种矢量图形格式，但也可以嵌入位图，因此不能保证所有内容无限放大都清晰。

有损压缩（Lossy Compression）以信息损失换取更小体积，JPEG 是常见实例。无损压缩（Lossless Compression）允许恢复原始编码数据，PNG 使用无损图像压缩。文件大小取决于内容、分辨率和编码参数，不能仅按扩展名判断。

五、实践：检查字节与字段

如果安装了 Python 3，可执行：

python -c "print('中'.encode('utf-8').hex())"

预期输出 e4b8ad。另建一个 UTF-8 文本文件保存上述 CSV 示例，使用文本编辑器和表格软件分别打开，检查编号前导零是否保留。只使用虚构记录，不覆盖原始业务数据。

六、与 Agent 协作

请定义导入数据的编码、字段类型、必填约束、空值语义和错误报告规则。保持编号的字符串类型，检查重复主键与非法数量；对 CSV 中的引号、换行、Unicode 和前导零提供测试。导出后重新导入并比较实际字段值。

七、知识检验

  • Unicode 与 UTF-8 为什么不是同一个概念？
  • 同一整数的字节序为什么会影响协议解析？
  • CSV 为什么可能丢失编号前导零？
  • JSON 格式合法是否意味着数据有效？

进阶方向：Unicode 正规化、IEEE 754、二进制协议、Protocol Buffers、数据模式演进。参考 RFC 3629（UTF-8）、RFC 8259（JSON）。
