第八部 · 软件工程

软件测试不是打开程序看一眼

报名程序已经有明确的规则。我们希望每次修改代码之后，都能够检查这些规则是否仍然成立。

如果每次都靠人打开网页、输入姓名、观察剩余名额，那么随着功能增加，检查工作会变得越来越容易遗漏。

把检查也写成程序

第 13 章已经介绍函数。我们可以直接调用一个报名函数，比较得到的结果与预期结果：

def register(total, registered):
    if registered >= total:
        return registered, False
    return registered + 1, True

assert register(20, 19) == (20, True)
assert register(20, 20) == (20, False)
assert register(20, 0) == (1, True)

assert 是 Python 中用于检查条件的语句。正常执行时，条件成立就继续；条件不成立会产生 AssertionError。正式测试通常使用测试工具提供的断言和执行环境，而不是将 assert 当作生产输入验证机制。

一组具有初始条件、操作和预期结果的检查可以构成测试用例（Test Case）。将检查过程交给程序执行，称为自动化测试（Automated Testing）。

不同测试检查不同边界

直接检查 register 函数是一种单元测试（Unit Test）：重点是某个有限范围的计算规则。

但即使函数完全正确，后端也可能没有正确调用它，数据库也可能没有保存记录。检查多个真实组件能否正确协作，通常称为集成测试（Integration Test）。

如果测试从浏览器或其他真实业务入口发起请求，并检查整个应用最终行为，就属于端到端测试（End-to-End Test，E2E）的一种形式。

不同范围的测试具有不同的成本和定位能力。只做端到端测试可能难以迅速判断错误来自哪里；只做单元测试又无法证明所有组件已经正确连接。

测试应该主动寻找边界

对于最多 20 人的报名系统，0、19、20 都是有意义的测试数据。还需要根据接口约定检查非法数据、重复请求、并发请求、数据库失败和程序重启等情况。

尤其是只剩一个名额时，同时发出两个报名请求，必须验证最终数据没有超过容量。这比顺序调用两次函数更接近真正需要保护的约束。

让测试真正报告失败

Python 标准库 unittest 可以组织独立测试用例：

import unittest

def remaining(total, registered):
    if not 0 <= registered <= total:
        raise ValueError("invalid count")
    return total - registered

class CapacityTests(unittest.TestCase):
    def test_last_slot(self):
        self.assertEqual(remaining(20, 19), 1)

    def test_full(self):
        self.assertEqual(remaining(20, 20), 0)

    def test_invalid(self):
        with self.assertRaises(ValueError):
            remaining(20, 21)

suite = unittest.defaultTestLoader.loadTestsFromTestCase(CapacityTests)
result = unittest.TextTestRunner().run(suite)
assert result.testsRun == 3
assert result.wasSuccessful()

测试运行器负责执行用例、收集错误并报告结果。这里额外检查了实际执行的测试数量，避免没有发现任何测试却误以为检查成功。

测试替身（Test Double）是用来替代某些真实依赖的测试组件。例如可以用一个受控对象模拟数据库失败，以检查应用如何报告错误。但模拟通过不能证明真实数据库也正常，仍应安排适当的集成测试。

测试通过不等于没有缺陷

测试只能够提供关于已检查条件的证据。测试用例可能漏掉情形，也可能将错误行为写成预期结果。

代码覆盖率（Code Coverage）描述哪些代码或分支在测试中被执行过。覆盖率高并不能证明每种行为都经过正确验证。

使用 AI 开发时，可以要求它为新增行为提供自动测试，同时检查测试是否真的在失败时报告错误。不能只接受它说「测试通过」，还应该查看执行命令和实际结果。
