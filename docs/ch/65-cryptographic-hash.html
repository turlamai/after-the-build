第九部 · 安全与隐私

怎样知道文件有没有发生变化

第四部讲过软件更新。假设我们下载了一份安装包，希望确认得到的内容与发布者提供的文件一致。

逐字节比较两个文件是一种直接办法。但如果我们手中只有下载结果，并没有另一份原始文件呢？

将任意长度的数据映射成固定长度结果

哈希函数（Hash Function）可以根据输入计算一个摘要值。密码学哈希函数（Cryptographic Hash Function）还需要满足相应的安全性质。

例如 SHA-256 将输入字节映射为 256 位摘要。通常以 64 个十六进制字符显示。

import hashlib

data = b"abc"
digest = hashlib.sha256(data).hexdigest()
print(digest)
assert digest == "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"

这里 b"abc" 表示由三个 ASCII 字符对应字节组成的数据。hexdigest 返回十六进制形式的摘要。

相同算法与相同输入会得到相同摘要。输入发生变化时，安全哈希函数通常会产生难以预测的不同结果。

为什么摘要不是压缩文件

任意长度的输入被映射到有限长度的摘要，必然存在不同输入具有相同摘要的情况。这称为碰撞（Collision）。

密码学哈希的目标不是让碰撞在数学上不存在，而是使寻找相应碰撞等攻击在预期安全条件下难以实现。

摘要也不是可逆的数据保存形式。一般不能从摘要恢复原始文件。

哈希能证明什么

假设可信渠道已经提供正确摘要，我们就可以计算下载文件的摘要并比较。不同摘要能够证明输入不相同；匹配则在适当的算法及信任条件下为内容一致提供很强的证据。

但如果文件和摘要都来自同一个已被篡改的页面，修改者可以重新计算新摘要。因此普通哈希并不能单独证明文件来自真正的发布者。

后面讲解数字签名时，我们会建立验证来源的机制。

共享秘密怎样帮助验证消息

如果通信双方已经安全取得同一个秘密密钥，可以利用消息认证码（Message Authentication Code，MAC）验证消息与密钥之间的关系。这里的 MAC 与网络章节中的 MAC 地址是不同概念。

HMAC 是使用哈希函数构造消息认证码的一类标准机制。下面使用公开的教学密钥验证消息变化会导致认证失败：

import hmac
key = b"public-teaching-example"
message = b"capacity=20"
tag = hmac.digest(key, message, "sha256")
expected = hmac.digest(key, b"capacity=21", "sha256")
assert not hmac.compare_digest(tag, expected)
assert hmac.compare_digest(tag, hmac.digest(key, message, "sha256"))

真实密钥必须通过合适的机制生成和保护。HMAC 不隐藏消息，也不能区分多个共享同一密钥的参与者。已经合法认证的旧消息还可能被重复发送，因此需要根据协议检查请求标识、序号、时间或其他新鲜性条件。这就是防重放（Replay Protection）需要解决的问题。

密码为什么不能直接用普通哈希保存

服务端需要验证输入密码是否正确，但不应该直接保存可供读取的原始密码。

简单使用 SHA-256 处理密码仍然不够，因为人类选择的密码往往可以被猜测，而普通哈希通常计算得很快。

专门的密码哈希方案，例如 Argon2id，利用适当的计算和内存成本增加批量猜测的难度。每个密码还应使用独立随机盐值（Salt），减少相同密码得到相同保存结果以及预先计算的收益。

盐值不是密码，也通常不需要保密。实际系统应采用成熟密码验证库并根据当前安全指导配置，而不是把本章 SHA-256 教学示例直接用于保存密码。

哈希主要提供摘要能力，不负责让原始数据对外不可读。下一章研究怎样让获授权者能够恢复数据，而其他人难以读取。
