第五部 · 网络与 Web

为什么 localhost 只能访问自己的设备

序章提出了一个问题：软件在自己电脑的浏览器中已经正常显示，为什么把地址发给其他人，对方却不能打开？

现在我们具备了完整解释这个现象所需要的基础知识。

localhost 指向哪里

localhost 是用于本地主机的特殊名称。常见系统将它解析为回环地址，例如 IPv4 的 127.0.0.1 或 IPv6 的 ::1。

回环（Loopback）通信由本机网络机制处理，不需要把相应数据发送到另一台物理设备。

因此，当你打开 http://localhost:8000 时，访问的是自己设备上的相应服务。朋友在他的电脑输入同一个地址，访问的则是他自己的设备。

这不是域名失效，也不一定是代码错误，而是地址本来就具有这样的含义。

亲自建立一个本地服务

如果已经安装 Python 3，可以创建一个专门用于实验的空目录，在其中保存第 37 章的 HTML 内容为 index.html。

进入该实验目录，使用以下命令启动 Python 自带的简单 HTTP 服务：

python3 -m http.server 8000 --bind 127.0.0.1

Windows 上也可以根据已安装的启动方式使用 python 或 py -3。

随后在同一设备的浏览器打开 http://127.0.0.1:8000/。如果服务成功启动且端口可用，就应能看到实验页面。

这个服务用于教学和本地实验，不适合作为正式公网业务服务器。只应在专门的实验目录中使用，不要在包含私人文件的目录中启动它。

实验结束后，可以在运行服务的终端按 Ctrl+C 结束进程。

服务监听地址决定什么

前面学习套接字时，我们已经知道服务可以绑定特定地址。

如果服务只绑定 127.0.0.1，其他设备通常不能通过本机局域网地址访问它。

如果需要经过局域网访问，则还需要考虑服务绑定的地址、客户端能否到达目标设备、端口是否开放以及防火墙策略。

绑定 IPv4 通配地址 0.0.0.0 通常表示监听本机相应的所有 IPv4 接口，而不是提供一个应当输入浏览器的公网目的地址。这样做可能扩大服务暴露范围，应结合实际授权和安全需求决定。

公网访问还需要哪些条件

即使局域网中的另一台电脑已经可以打开页面，互联网中的其他人也不一定能够访问。

公网可达需要适当的地址及路由条件、服务监听、网络访问策略，以及合理的安全保护。若使用域名，还需要正确的 DNS 配置。仅购买域名并不会自动使自己的电脑成为公网服务器。

一种常见选择是将应用部署到具有合适网络环境的服务平台，而不是随意向互联网开放个人电脑。

部署（Deployment）是将应用及所需配置放入目标运行环境，使其能够按照预期提供功能的过程。部署并不只是上传文件，也不意味着必须购买一台物理服务器。

用分层知识诊断问题

现在，当网站不能打开时，我们可以先区分以下问题：

  • 应用进程是否启动，是否在预期地址和端口监听？
  • 客户端使用的地址是否指向正确目标？
  • 两台设备之间是否有可达路径，访问是否被策略限制？
  • DNS 是否返回预期记录？
  • HTTP 请求是否获得响应，业务是否正常？

这不是一套保证适用于所有故障的固定操作顺序，而是一种使用不同层次的已知机制缩小问题范围的方法。
