第一部 · 信息与计算

计算机为什么会出现乱码

在纸上写一个 A，我们可以直接认出它。但计算机内部保存的是二进制状态，并没有一个物理部件专门存放字母 A 的形状。

因此，必须制定一种规则，把文字中的字符转换成数字，再将数字表示成二进制。

从给字符编号开始

早期有许多不同的文字编码约定。ASCII 是其中一项重要的标准，它定义了 128 个编码值，对应英文字母、数字字符、标点以及一些控制用途。

例如，大写 A 对应十进制 65，小写 a 对应 97，数字字符 0 对应 48。

这里必须区分数字 0 和文字中的字符 0。前者在某种数值表示中可以使用全为零的位；后者按 ASCII 编码，其编码值是 48，即十六进制 0x30。

如果按照 ASCII 规则记录文字 A0，就得到两个字节：

字符 字节的十六进制表示
A 41
0 30

把这两个字节当成数字进行计算，与按照 ASCII 把它们还原成文字，是两种不同的操作。

只有 128 个编号显然不够

汉字、日语、阿拉伯文字和其他语言所需要的字符，远远超过 ASCII 的范围。不同地区曾使用不同的扩展编码。如果两台计算机使用的约定不同，交换文字就可能产生问题。

为了让世界各地的文字在统一的体系中得到表示，产生了 Unicode 标准。它为字符分配编号，这种编号称为码点（Code Point）。

例如，大写 A 的码点为 U+0041，汉字「中」的码点为 U+4E2D。

Unicode 码点说明字符在统一编号体系中的位置，却还没有说明编号要怎样转换成连续字节。UTF-8 是其中一种实际编码方式，它规定怎样使用一到四个字节表示一个 Unicode 标量值。

在 UTF-8 中，A 使用一个字节 41，而「中」使用三个字节 E4 B8 AD。

UTF-8 怎样将码点变成字节

ASCII 的全称是 American Standard Code for Information Interchange（美国信息交换标准代码）。UTF-8 保留了 ASCII 的单字节编码，并为更大范围的 Unicode 码点安排多字节表示。

UTF-8 只编码 Unicode 标量值：从 U+0000 到 U+10FFFF，排除为 UTF-16 保留的代理码点 U+D800 到 U+DFFF。

码点范围 字节结构
U+0000 至 U+007F 0xxxxxxx
U+0080 至 U+07FF 110xxxxx 10xxxxxx
U+0800 至 U+FFFF（排除代理码点） 1110xxxx 10xxxxxx 10xxxxxx
U+10000 至 U+10FFFF 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx

表中 x 是用来填入码点二进制数据的位置。字节开头的固定位则帮助读取程序识别一个编码序列的结构。

以「中」为例，码点 0x4E2D 的 16 位表示为 0100111000101101。它属于三字节范围。将二进制从右向左分成 6 位、6 位、4 位，即 0100、111000、101101，再填入 1110xxxx、10xxxxxx、10xxxxxx：

字节 填入之后 十六进制
第一字节 11100100 E4
第二字节 10111000 B8
第三字节 10101101 AD

读取程序依照相反方向组合有效位，恢复码点。实际解码还要检查序列是否完整、是否合法，以及是否使用了正确的最短编码形式。

UTF-8 的变长表示解释了为什么同一份文本中，英文字母与汉字所占字节数可能不同。

字符、码点、字节和屏幕上的形状不是一回事

一个字符可能需要多个字节。有些用户看到的一个完整符号，也可能由多个码点组成。例如某些带附加符号的字母或者组合表情。

屏幕上最终显示的形状还受到字体等因素影响。字体提供文字显示所需的字形信息，而字符编码负责记录文字的表示。这是两种不同的工作。

因此，不能简单地用字节数量计算文本中用户看到的字符数量。

乱码是怎样发生的

假设一份文字按 UTF-8 保存，读取它的程序却按另一种编码解释这些字节。读取过程可能得到完全不同的字符，也可能遇到无法解释的序列。

这就是常见乱码产生的机制之一。还有一种情况是编码读取正确，但设备缺少能够显示相应字符的字体。两种问题看起来都可能是文字显示异常，却需要不同的解决方法。

尤其不要把已经错误解码的文字直接覆盖保存。重新保存可能改变原有字节，使问题更难恢复。

如果有一天你让 AI 帮你处理一份包含中文姓名的记录，不妨明确告诉它：输入和输出采用 UTF-8，保留原始数据，并用包含中文和特殊字符的样例验证结果。

我们此时已经有足够的知识理解文字是怎样被记录的。接下来要研究的是，计算机如何对这些表示进行处理。
