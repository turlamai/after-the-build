第一部 · 计算机技术基础

第 2 章 计算机硬件：数据、指令与存储层次

学会区分计算资源、内存资源、持久化存储及其性能指标。

一、数据如何表示

比特（Bit）是二进制信息的基本单位，取值为 0 或 1。字节（Byte）通常由 8 个比特构成，可表示 256 种不同的位组合。同一组比特可以表示整数、字符、机器指令或图像数据，具体含义取决于编码和数据类型。

例如十六进制 0x41 对应二进制 01000001，在 ASCII 编码中表示字符 A，作为无符号整数则表示 65。第 8 章将进一步解释字符编码和文件格式。

容量单位需要区分十进制与二进制：1 GB = 10 亿字节，而 1 GiB = 2 的 30 次方字节。网络速率通常以 bit/s 表示，文件大小通常以 byte 表示，两者不能直接比较。

二、CPU 如何执行程序

中央处理器（Central Processing Unit，CPU）执行机器指令。指令集架构（Instruction Set Architecture，ISA）定义软件可见的指令、寄存器及相关行为。例如 x86-64 和 AArch64 是不同的指令集架构，因此编译生成的本机可执行文件通常不能直接跨架构运行。

寄存器（Register）是处理器内部保存操作数、地址和状态的存储资源。程序计数器（Program Counter，PC）记录执行位置相关的信息。典型指令执行包含取指、译码、执行及结果提交等阶段；现代处理器可能使用流水线、乱序执行和分支预测，实际执行并非严格逐条完成。

时钟频率（Clock Frequency）表示每秒时钟周期数，3 GHz 表示每秒约 30 亿个周期，而非必然执行 30 亿条指令。性能还受每周期完成指令数、内存访问延迟、算法和工作负载影响。

核心（Core）是具备独立执行能力的处理单元。多核可以并行执行任务，但只有能够并行化的程序才能充分获益。线程（Thread）是操作系统调度执行的重要单位，第 7 章详述。

三、内存和持久化存储

资源 功能 典型特点
寄存器 保存当前指令所需数据 容量小、访问快
缓存（Cache） 保存近期或频繁使用的数据 通常分为 L1、L2、L3 等级
主存（RAM） 保存运行中的程序和数据 通常断电丢失
固态硬盘（SSD） 持久化保存文件 非易失，访问延迟通常高于 RAM

缓存利用时间局部性和空间局部性降低主存访问成本。缓存未命中（Cache Miss）时，需要从更低层次读取数据。程序性能因此不只取决于 CPU 算术能力。

运行程序时，操作系统将可执行文件的相关内容映射到进程地址空间，并按需读取。并非所有文件都必须一次性完整载入内存。内存不足时，系统可能回收缓存、换页或终止进程；存储空间不足则可能导致写入失败。两类问题需要不同证据。

四、GPU 与 AI 加速

图形处理器（Graphics Processing Unit，GPU）具备适合大规模并行运算的硬件资源，常用于图形渲染和矩阵运算。显存（Video RAM，VRAM）或统一内存用于存放模型权重、中间结果等数据。神经网络处理器（Neural Processing Unit，NPU）则是针对部分神经网络运算设计的加速器。

以本地推理为例，一个 70 亿参数模型若每个参数使用 16 bit，权重理论大小约为 14 GB；采用 4 bit 量化时，理想权重大小约为 3.5 GB。实际运行还需要量化元数据、缓存及运行时内存。能存下模型文件不代表能够高效运行模型。

五、实践：观察真实资源

打开 Windows 任务管理器、macOS 活动监视器或 Linux 系统监视器，查看 CPU 使用率、内存占用、磁盘活动和可用容量。记录空闲状态，再运行一个常用应用，对比资源变化。

不要单凭某项利用率高就认定故障。还要观察持续时间、响应延迟和系统是否出现内存压力或 I/O 等待。

六、与 Agent 协作

请检查当前程序的 CPU 利用率、内存峰值和磁盘 I/O；记录硬件架构与运行环境，使用代表性工作负载复测。先提供性能证据，再提出优化方案，不直接增加硬件配置。
