第一部 · 计算机技术基础

第 7 章 操作系统：进程、内存与资源管理

操作系统定义应用程序访问硬件和系统资源的方式。

一、系统的层次

操作系统（Operating System，OS）管理计算机资源，并为应用程序提供运行环境。内核（Kernel）负责调度、内存管理及设备访问等核心功能。用户空间（User Space）中的普通应用通过系统调用（System Call）请求内核提供服务，例如打开文件、创建进程或建立网络连接。

设备驱动（Device Driver）负责与特定硬件或虚拟设备交互。不同系统的驱动与应用程序接口不同，因此相同硬件架构上的程序也可能无法跨操作系统直接运行。

系统启动通常涉及固件初始化、引导加载程序（Bootloader）、内核启动及系统服务初始化。具体流程因设备和系统而异。

二、程序、进程与线程

程序（Program）是描述计算过程的指令及相关数据。进程（Process）是程序运行时的实例，通常具有独立虚拟地址空间、进程标识符（PID）和资源。线程（Thread）是进程中的执行序列，通常共享同一进程的地址空间及部分资源，但有自己的执行上下文和栈。

调度器（Scheduler）决定哪些可运行线程获得 CPU 时间。单核可以通过上下文切换（Context Switch）交替执行多个线程；多核则可以真正并行执行多个线程。

进程终止不等于程序文件被删除；删除程序文件也不保证现有进程立即退出。程序崩溃后通常可以重新启动，但未持久化的状态可能丢失。

三、虚拟内存与隔离

虚拟内存（Virtual Memory）为进程提供虚拟地址空间，由硬件和操作系统共同完成地址转换与访问权限控制。虚拟地址不等于物理 RAM 地址，地址空间也不等于实际内存占用。

页（Page）是常见的内存管理单位。访问尚未建立有效映射的页面可能触发缺页异常（Page Fault），操作系统可能按需加载数据；非法访问则可能导致进程异常。交换空间（Swap）可用于部分内存数据的换出，但不能替代高性能 RAM。

进程隔离有助于限制普通应用之间的相互干扰，但不是绝对安全边界。内核漏洞、共享资源和过度权限都可能导致影响扩散。

四、权限与进程通信

操作系统依据用户身份、文件权限、访问控制列表或沙箱策略判断访问是否允许。管理员权限可以改变更多系统状态，因此不要为解决普通配置错误就直接以管理员身份运行应用。

进程间通信（Inter-process Communication，IPC）可以通过管道、共享内存、消息队列或套接字实现。浏览器、数据库和桌面应用常由多个进程协作，不应假设每个浏览器标签页必然对应一个独立进程。

五、服务及运行环境

后台服务（Service 或 Daemon）通常不依赖可见窗口，由系统或服务管理器启动、监控和停止。例如 Web 服务可以在 Linux 中由 systemd 管理。是否自动重启、以谁的身份运行以及日志存放位置，取决于配置。

Linux 是内核，也常用于指代基于 Linux 内核的完整操作系统发行版。Windows、macOS 和 Linux 的路径、权限、命令及二进制接口存在差异。部署时必须确认目标平台，而不能假设开发机与服务器行为一致。

六、实践：查看进程状态

在任务管理器或活动监视器中找到一个应用的 PID、CPU 和内存指标。在 macOS 或 Linux 终端可以执行 ps -ef，在 PowerShell 可以执行 Get-Process 查看进程。

启动一个普通应用，观察新增进程；正常退出后确认对应进程是否消失。某些应用仍保留后台服务，这是设计行为，不一定是故障。不要结束未知的系统进程。

七、与 Agent 协作

请识别服务进程 PID、运行用户、启动命令、监听端口和退出状态，检查日志及内存压力。先区分进程未启动、异常退出、仍在运行但不响应等情况；未经授权不要终止其他进程或提升权限。

八、知识检验

  • 进程与线程共享哪些资源？
  • 虚拟地址为什么不等于物理地址？
  • 为什么进程仍存在却可能无法提供服务？
  • 强制终止进程可能损失哪些数据？

进阶方向：系统调用、进程调度、页表、同步原语、死锁与实时操作系统。
