第二部 · 计算机内部

一串数字怎样成为程序

我们现在已经有了能够进行运算的电路、能够保存结果的寄存器，以及能够根据地址访问数据的存储器。

这些部件各自能够完成任务，但谁来告诉它们先做什么、再做什么？如果每次运算都需要人去改变电路的控制信号，计算机就很难自动完成复杂工作。

把操作要求也表示成数字

我们在第一部学习过编码：可以用同样的二进制符号表示不同含义，只要明确解释规则。

同样，我们可以给硬件能够执行的操作编号。例如规定某些位表示读取一个数，另一些位表示相加，还有一些表示保存结果。

处理器能够识别并执行的这种编码叫机器指令（Machine Instruction）。

指令不仅要说明做什么，还可能要指出使用哪些数据。例如「将寄存器 R1 与 R2 的数相加，将结果写入 R1」。

其中表示操作种类的编码叫操作码（Opcode）；指定使用哪些数据、寄存器或位置的信息常称为操作数（Operand）或操作数字段。

并非每条指令都有完全相同的字段。这里先使用一个简单的教学模型。

一组指令就能完成任务

假设我们设计了一台简化的计算机，有两个寄存器 R1 和 R2，以及一块可读写的存储器。数据地址 100 保存 3，地址 101 保存 5。

我们希望计算两数之和，并写入地址 102。可以把任务拆成四条操作要求：

顺序 教学指令 执行后的变化
1 LOAD R1, 100 R1 保存 3
2 LOAD R2, 101 R2 保存 5
3 ADD R1, R2 R1 保存 8
4 STORE R1, 102 地址 102 保存 8

LOAD、ADD 和 STORE 是便于阅读的符号名称，并不是硬件直接识别的文字。真实的机器指令会按处理器规定的二进制格式保存。

上表是为理解机制而定义的教学指令，不对应某个实际处理器的完整语法。

将这些指令组织起来，就形成了一个简单的程序（Program）。程序是计算过程的一种表达；它可以包含操作要求，以及运行所需的相关数据。

亲自规定一种机器指令的编码

前面的 LOAD 和 ADD 还是文字。为了看清机器指令的实际含义，我们设计一种虚构的 16 位固定长度教学编码：

  • 最高 4 位规定操作码：1 表示 LOAD，2 表示 ADD，3 表示 STORE。
  • 接下来 4 位表示第一个寄存器编号。
  • 最低 8 位在 LOAD 和 STORE 中表示数据地址，在 ADD 中表示第二个寄存器编号。

只有本节规定的寄存器和操作码有效。这个格式不是任何真实处理器的 ISA。

教学指令 操作码 第一寄存器 地址或第二寄存器 16 位十六进制编码
LOAD R1, 100 1 1 0x64 0x1164
LOAD R2, 101 1 2 0x65 0x1265
ADD R1, R2 2 1 0x02 0x2102
STORE R1, 102 3 1 0x66 0x3166

例如，0x1164 的二进制形式为 0001 0001 01100100。硬件根据最高四位识别出 LOAD，再根据后面四位选择 R1，并根据最低八位取得地址 100。

这些编码可以像普通数据一样保存。真正决定它们被解释为指令还是数据的，是处理器在相应时刻进行的操作以及系统的访问规则。真实 ISA 的指令长度、操作数字段和地址计算方式可能更复杂。

谁来决定下一条指令

如果指令存放在可访问的存储位置中，计算机还需要保存下一次应该去哪里取得指令的信息。

为此，处理器通常具有与指令位置相关的寄存器，常称程序计数器（Program Counter，PC）。

在最简单的模型中，每执行一条指令，PC 就更新为下一条指令的位置。但有些指令可以改变执行顺序。

例如，报名程序需要判断是否还有名额。如果没有，就跳过增加人数的操作，直接进入提示拒绝的步骤。这就需要根据判断结果改变后续的指令位置。

改变执行位置的指令常被称为跳转或分支指令（Branch Instruction）。它使程序能够根据条件选择不同的行为，也可以反复执行某些指令。

为什么不同处理器的指令可能不同

不同的处理器可能提供不同的寄存器、指令和编码规则。这些软件可以观察、使用的机器行为构成了指令集架构（Instruction Set Architecture，ISA）的重要内容。

例如 x86-64 和 AArch64 是不同的指令集架构。为其中一种架构生成的本机机器代码，通常不能在另一种架构上直接执行，除非借助转换或模拟等机制。

现在我们已经有了理解 ISA 的基础：它不是某个抽象的产品名称，而是软件与处理器之间关于机器指令及其行为的约定。
