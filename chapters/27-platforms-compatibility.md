# 为什么同一个软件不能在所有设备上运行

假设我们完成了报名软件，并将它打包成 Windows 可执行文件。朋友使用 macOS，能否直接运行这个文件？

根据前面学习的知识，我们可以逐层判断，而不是先给出一个简单的「可以」或「不可以」。

## 第一层：处理器能否执行指令

第二部介绍了指令集架构。如果可执行文件包含为 x86-64 生成的机器代码，而目标设备使用 AArch64，通常不能直接执行这些指令。

某些系统提供指令转换或模拟机制，但能否运行还取决于软件及系统的具体条件。

因此，即使两台电脑使用相同操作系统，也可能需要不同架构的构建产物。

## 第二层：操作系统是否提供所需接口

假设两台电脑都采用同一种处理器，程序是否就一定能够运行？

不一定。我们已经知道普通程序需要通过系统接口访问文件、创建窗口及获取设备服务。不同操作系统提供的接口可能不同，还采用各自的程序装载和文件格式规则。

这也是为什么 Linux 上的本机程序并不必然能在 Windows 上直接执行。

程序与系统在二进制层面需要遵守的调用规则等约定，通常称为应用程序二进制接口（Application Binary Interface，ABI）。

ABI 与前面学习过的 API 有关，但关注层次不同。API 描述怎样调用功能；ABI 还涉及已经转换成机器可执行形式的程序如何进行兼容的交互。

## 第三层：运行环境和依赖是否存在

一些程序依赖特定版本的运行时或动态链接库。动态链接库是一类能够在程序装载或执行期间按需使用的已编译代码组件。

即使处理器和操作系统都符合要求，如果缺少所需组件，程序也可能无法启动。

操作系统版本、图形设备功能和权限规则同样可能影响应用是否正常工作。

## 跨平台软件如何减少重复开发

跨平台开发（Cross-platform Development）尝试让不同平台共享部分源代码及软件组织方式，并由相应工具处理平台差异。

这并不意味着只生成一个文件就能运行于所有设备。开发者可能仍然需要分别构建 Windows、macOS、Linux 或其他平台的版本，并在各目标环境中验证。

移动应用还需要考虑手机系统的权限与分发规则。嵌入式软件则可能需要直接面对设备内部的硬件约束。

浏览器应用使用浏览器提供的执行环境，因此可以减少部分操作系统差异，但仍受到浏览器版本、设备能力和相关接口支持情况的影响。

## 如何准确告诉 AI 你的目标平台

不要只说「帮我做一个桌面软件」。

可以说明目标是 Windows 11 的 x86-64 设备，还是同时支持 macOS 的 AArch64 设备；是否允许要求用户另装运行时；是否需要离线运行；最终要交付什么形式的安装包。

这些要求会直接影响架构选择、构建和测试。
