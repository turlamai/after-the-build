# 什么叫作计算

计算并不只意味着做加减乘除。假设我们要根据一份报名名单，判断还有没有剩余名额。

总名额是 20，已经报名的人数是 17。先用 20 减去 17，得到 3；再判断 3 是否大于 0。如果大于 0，就允许继续报名，否则提示名额已满。

这项任务包含了数值计算，也包含了比较和根据条件作出选择。它仍然可以由计算机完成。

## 把任务拆成明确的步骤

如果有人只告诉我们「处理报名」，我们无法知道应该检查什么。需要把规则进一步明确下来：

第一步，取得总名额和已报名人数。第二步，计算剩余名额。第三步，判断剩余名额是否大于零。第四步，根据判断结果给出允许或者拒绝的结果。

这些步骤描述了怎样把已有的信息转换成新的结果。我们把交给计算过程的数据称为输入（Input），计算过程产生的结果称为输出（Output）。

算法（Algorithm）是解决某类问题的明确步骤。这里的算法不依赖某个具体品牌的计算机，也不要求使用某一种编程语言。只要执行者能够正确执行这些步骤，就可以根据不同的输入得到相应的输出。

## 条件如何改变下一步

上面的第三步产生一个判断结果。对于「剩余名额大于零」这个命题，结果可以为真或假。这种二值逻辑常用布尔值（Boolean Value）表示。

布尔值可以用二进制位表示，但它与数值 0 或 1 的含义不同。它表达的是逻辑判断，不是数量。

如果两个条件都必须成立，就需要逻辑与（AND）；只要其中一个条件成立，就需要逻辑或（OR）；希望取得相反的判断，则使用逻辑非（NOT）。

例如允许报名不仅要求有剩余名额，还要求报名尚未截止。把两个判断结果组合：

| 有剩余名额 | 报名尚未截止 | 允许报名 |
|---|---|---|
| 否 | 否 | 否 |
| 否 | 是 | 否 |
| 是 | 否 | 否 |
| 是 | 是 | 是 |

这张表展示了逻辑与的全部可能输入和输出，称为真值表（Truth Table）。

### 逻辑或与逻辑非

逻辑或的含义是至少一个条件成立。假设工作人员可以通过邀请资格或普通报名资格中的任意一种进入活动：

| 有邀请资格 | 有普通资格 | 允许进入 |
|---|---|---|
| 否 | 否 | 否 |
| 否 | 是 | 是 |
| 是 | 否 | 是 |
| 是 | 是 | 是 |

注意，当两个条件都成立时，逻辑或仍为真。它不是日常语言中有时表示的「只能二选一」。

逻辑非只有一个输入：

| 输入 | NOT 的输出 |
|---|---|
| 假 | 真 |
| 真 | 假 |

如果报名截止这个条件为真，那么 NOT 报名截止为假。

### 怎样组合条件

考虑一条业务规则：有剩余名额，并且报名没有截止，或者工作人员具有补录资格。这里必须进一步明确，补录资格能否突破容量限制。

如果容量限制必须始终成立，正确组合是：

有剩余名额 AND（NOT 报名截止 OR 有补录资格）。

当容量已经用尽时，不论括号里的结果如何，最终结果都为假。括号明确规定了先组合哪些条件。这个区别将在后续的程序分支、数据库事务与权限控制中反复出现。

## 计算也可以改变记录

允许一个人报名后，已报名人数需要增加 1。下一次判断应使用更新后的人数，而不能一直使用最初的 17。

某一时刻需要保留、并可能影响后续处理的信息，可以称为状态（State）。在这个例子里，当前已报名人数就是状态的一部分。

计算的结果可以成为下一次计算的输入，状态则把多个时间点的操作联系起来。之后我们会用它理解程序中的变量、文件保存，以及为什么两个同时报名的人可能争抢最后一个名额。

## 正确的执行不一定产生正确的结果

如果我们不检查已报名人数是否已经超过总名额，或者允许输入负数，规则可能得到不符合实际要求的结果。

计算机只按照已经确定的规则进行操作，并不会自动知道什么叫「合理的报名人数」。因此，定义规则、明确输入约束并检查结果，是软件开发不可缺少的一部分。

AI 可以帮助我们表达这些规则，但它也需要知道我们的真实要求。
