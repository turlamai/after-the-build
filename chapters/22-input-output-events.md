# 软件怎样知道你点击了按钮

前面我们写过一个报名人数加一的小程序。它运行时按照预先写好的步骤计算，输出结果，然后结束。

但真正的报名软件不应该一打开就自动增加人数。它应该先显示当前人数，等待使用者输入姓名，等到使用者确认报名时才执行计算。

这意味着程序必须能够处理来自外部的输入，并根据输入发生的时间决定执行什么。

## 键盘上的一个按键怎样到达程序

按下一枚键时，键盘内部的电路会检测到按键状态发生变化。键盘通过与计算机约定的通信方式提供相关信息。

第三部已经讲过设备驱动：操作系统通过驱动与设备交互，并将适合应用处理的信息提供给相应程序。因此，报名应用通常不需要自己测量键盘内部的电信号。

从应用的角度来看，「某个键被按下」「鼠标移动到某个位置」都是可以获得并处理的事件（Event）。事件是对已经发生的事情的一种表示，通常还包含发生时间、位置或具体内容等相关信息。

一次物理按键并不必然对应一个最终字符。例如，输入中文时可能先使用多个按键选择候选字。应用接收到的文字输入与原始按键事件应当区别对待。

## 程序为什么不能从头到尾只执行一次

假设报名软件显示了一个确认按钮。我们事先并不知道使用者会在何时点击它，也不知道他会不会修改姓名。

一种常见的设计是让程序持续等待并处理事件。没有需要处理的工作时，可以借助系统机制等待，而不必一直占用处理器检查键盘状态。

负责反复取得并分派事件的机制通常称为事件循环（Event Loop）。当发生某种事件时，程序执行与它相关联的处理函数，这种函数通常称为事件处理器（Event Handler）。

这种根据事件决定执行行为的程序组织方式叫事件驱动（Event-driven Programming）。

## 事件如何排队，又如何找到处理函数

假设用户连续输入两个字符，然后点击确认按钮。应用可能先后收到三条事件记录。保存尚待处理事件的结构通常称为事件队列（Event Queue）。队列通常按进入顺序取出元素，但实际事件系统还可能合并事件、设置优先级或采用多个队列。

应用可以事先登记某种事件发生时应调用的函数。这类交给其他代码、等待适当时机调用的函数称为回调（Callback）。

下面用一个有限队列模拟事件分派。它不是实际窗口系统，也不需要真实键盘。先认识这里会使用的两种数据结构：元组（Tuple）用圆括号组织一组值，例如 ("input", "小林")；字典（Dictionary）用键和值建立查找关系，例如 {"name": "小林"}，可以用 state["name"] 取得对应的值。Python 允许函数作为值保存，因此我们也可以将事件名称与处理函数组织成字典。第 41 章会继续研究这些结构怎样表示和交换。

```python
from collections import deque

events = deque([("input", "小林"), ("submit", None)])
state = {"name": "", "registered": 19}

def on_input(value):
    state["name"] = value

def on_submit(_):
    if state["name"] and state["registered"] < 20:
        state["registered"] += 1

handlers = {"input": on_input, "submit": on_submit}
while events:
    kind, value = events.popleft()
    handlers[kind](value)

assert state["registered"] == 20
```

这里的队列耗尽后程序退出。真实界面通常会继续等待新事件，并由框架或操作系统协调等待与分派。

## 异步处理不等于创建一个新线程

如果读取报名记录需要等待较慢的设备，应用可以在请求完成之后再处理结果，而不是一直阻塞当前事件处理函数。这类允许任务发起后在适当时刻继续处理结果的组织方式称为异步（Asynchronous）处理。

异步任务可能利用系统的非阻塞接口、其他线程或其他进程，也可能在同一个事件循环中交替推进。不能从「异步」这个词推断代码必然在不同 CPU 核心上执行。涉及界面更新时还要遵守相应工具对线程及状态访问的约束。

## 把以前学过的规则接入事件处理

我们可以把报名计算规则组织成下面的函数：

```python
def register(total, registered):
    if registered >= total:
        return registered, "名额已满"
    return registered + 1, "报名成功"

count, message = register(20, 19)
print(count, message)
```

预期输出 20 报名成功。函数返回两个结果：更新后的报名人数，以及应该向使用者显示的消息。

在实际应用中，我们不必在软件启动时调用这个函数，而可以在使用者确认报名时调用它。

函数自身不关心使用者是点击按钮、按下回车，还是通过命令发出报名要求。这让同一项业务规则能够在不同的交互方式中复用。

这里还没有真正保存姓名，也没有处理多个同时报名的请求。这些问题将在数据与数据库部分解决。

## 等待不等于程序停止工作

事件处理函数如果执行一个十分耗时的任务，可能阻塞后续事件的处理，让界面无法及时响应。

这就是为什么有些应用正在工作时，窗口却看起来像是卡住了。解决办法可能涉及线程、独立进程或异步任务，具体取决于软件所使用的执行模型。

读者此时已经掌握进程和线程的概念，因此能够理解这里的取舍：不是简单地让处理器更快，而是合理组织工作，确保交互所需的任务能够及时执行。
