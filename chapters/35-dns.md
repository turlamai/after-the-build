# 输入一个名字，计算机怎样找到网络地址

前面我们使用 IP 地址访问服务。如果把报名服务从一台机器迁移到另一台机器，地址可能改变。

我们希望使用者仍然可以使用同一个名称，而不必每次记住新的地址。

## 域名与 IP 地址

域名（Domain Name）是按照一定命名结构组织的名称，例如 registration.example.com。

这里使用 example.com 这一保留的示例域名。它不代表我们已经部署了真实报名服务。

域名通常由点分隔的标签组成。命名体系具有层次结构，相关管理者可以按照规则管理相应范围内的名称。

但名称本身不能直接代替网络传输所需的全部地址信息。计算机需要按照规则查询与名称相关的数据。

域名系统（Domain Name System，DNS）提供了分布式的名称查询机制。

## 查询怎样得到结果

当程序需要访问一个域名时，通常会借助操作系统的名称解析能力。系统可能先检查缓存、本地配置等信息，再向配置的 DNS 解析服务发起查询。

在需要进行完整 DNS 查询时，递归解析器可以沿域名体系寻找负责相应名称的权威服务器，取得记录并返回结果。

A 记录用于提供 IPv4 地址，AAAA 记录用于提供 IPv6 地址。DNS 还支持许多其他记录类型，因此不能把它理解为只会返回 IP 地址的简单表格。

## 为什么修改记录不会立刻影响所有用户

DNS 结果可能被不同层次的系统缓存。记录中通常包含生存时间（Time To Live，TTL），表示该记录在缓存中允许保留的时间相关信息。

如果某个解析器之前已经获得旧记录，修改权威记录后，它可能仍在一段时间内使用尚未过期的结果。

此外，操作系统和应用还可能采用自己的缓存及连接复用机制。

因此，排查域名迁移问题时，必须区分权威记录是否已经修改、各解析器当前获得什么结果，以及应用实际上连接了哪个地址。

## 一个可观察的练习

如果设备提供 nslookup，可以尝试：

```sh
nslookup example.com
```

这项操作需要能够使用相应的解析服务。实际地址和显示格式可能因时间及环境而变化，本书不指定一个永远不变的输出。

域名解析成功并不等于目标应用可用。DNS 可以正确返回地址，而服务器没有运行，端口仍可能不可访问。
