# 附录 B 问 AI 的模板库

> 全书教过的「怎么问」，收拢成八个可以直接复制的模板。填空，发送，省掉大半的来回。

## 动手之前：需求澄清

用途：让 AI 做东西之前，先把猜的空间挤掉（第 5 章）。

```text
我想做一个：……（一句话说清它是什么、给谁用）
使用者会在什么设备上打开：手机 / 电脑 / 都要
它需要：……（列出功能，每条一句）
它不需要：……（明确排除的，防止 AI 自由发挥）
数据存在哪里、要不要登录：……
验收标准：手机上打开不横滚；点提交出现「已收到」；……
请先复述你的理解和方案，确认后再动手。
```

## 改需求：小步走

用途：任何改动，一次只提一件事（第 5、14 章）。

```text
只改：……（一个点）
不要动：其他任何文件的任何部分。
改完之后，告诉我你动了哪几个文件，我再验收。
```

## 排错：六栏模板

用途：出问题向 AI 求助的黄金格式（第 14 章）。

```text
我在做：……
我做了：第一步、第二步。
我期望：……
实际发生：……
完整报错：（原样贴上，不要转述）
我试过：……（列出来，避免重复建议）
```

## 学习：概念补习

用途：答不上「四十个问题」里的某一条时，回炉补课（第 8、24 章）。

```text
请给我讲讲：……（概念名）
深度要求：讲到我能预测后果为止，不要讲到能实现为止。
不用教我怎么做，用生活比喻讲清楚「它为什么存在、它坏了会怎样」。
最后给我三个例子：什么情况下我会遇到它。
```

## 上线：部署求助

用途：第一次部署或部署失败时（第 13 章）。

```text
我的项目：……（纯网页 / 带登录、带数据库）
代码在：GitHub 仓库（链接）
我想要的：一个别人能打开的网址，免费方案优先。
我已经做了：……
卡在哪一步：……（贴报错原文）
请给我当前这一步的操作，一次只给一步。
```

## 安全：让 AI 扮演坏人

用途：上线前自查（第 19 章）。

```text
假设你是一个安全测试员，目标是偷走这个网站的用户数据。
列出你最先尝试的五条路，然后逐条告诉我：现在通不通、怎么堵上。
我的项目信息：……（网址、功能、存了什么数据，不要发密钥）
```

## 钱：成本盘点

用途：月度盘点日或怀疑多扣钱时（第 16 章）。

```text
我用了这些服务：……（每个一行，写明套餐或用量）
请帮我算两笔账：
一、目前这个用量，每月大概花多少钱；
二、最失控的情况下（用量翻十倍、超额自动转付费），最坏一个月多少钱。
哪些服务建议设用量上限，请一并告诉我。
```

## 求人：一页纸说明书

用途：找朋友或付费咨询时，随信附上（第 21 章）。

```text
现状：它是什么，现在怎么坏。
目标：修好之后达到什么效果。
约束：什么不能动（数据、时间、预算）。
期限：什么时候要。
验收：怎么算修好了。
附：报错原文、最近一次改动、复现步骤。
```

## 用模板的三个提醒

模板不是咒语，是骨架。填空时越具体越好，「不太对」「感觉坏了」这类描述，AI 和朋友都无从下手。

一次只发一个模板对应一件事。排错的信里夹一个新需求，等于让医生一边看病一边听你讲装修计划。

答不上来就追问。AI 的第一次回答常常不是最好的那个，说「再具体一点」「给我分步操作」，它不会烦。
