# 与 Agent 协作的任务模板

模板的目的不是规定固定提示词，而是将需求、证据和权限明确表达出来。先阅读[第 54 章](./54-requirements.html)、[第 56 章](./56-software-testing.html)与[第 81 章](./81-agent-verification.html)。

## 修改现有功能

```text
目标：描述当前行为与目标行为。
依据：先核对当前分支、相关文件及已有测试。
约束：列出必须保留的接口、数据和行为。
验收：指定可重复的检查及预期结果。
权限：仅允许在测试分支修改，不直接发布。
交付：列出实际修改、测试结果和仍未解决的问题。
```

## 排查故障

提供可复现步骤、版本、环境、实际错误与预期行为。要求先分析证据，再进行最小必要修改，并添加回归测试。参见[第 57 章](./57-debugging.html)。

## 审查发布

核对提交、CI、构建产物、部署环境、数据迁移及回滚方案。明确发布授权，不能把创建 PR 当成发布成功。参见[第 59 章](./59-ci-build-pipeline.html)与[第 60 章](./60-release-and-rollback.html)。

## 学习陌生技术

先说明已经理解的概念，要求从必要前置知识解释新机制，提供最小可验证示例，并明确适用边界。不要把未经工具验证的陈述当作真实执行结果。
