# 附录 B AI Agent 工程协作模板

> 模板用于组织任务规格与验收证据，不是保证模型正确的提示词技巧。按实际项目填写，不提供真实密钥或无授权数据。

## 一、需求与架构（第 1、12、22 章）

```text
目标及用户：
使用平台与运行环境：
功能需求：
非功能需求（安全、延迟、容量、可靠性）：
数据模型及外部接口：
约束及不在范围内的事项：
验收标准：
请比较候选架构，记录关键假设、取舍和风险。
```

## 二、概念学习（全书）

```text
请解释以下技术术语：[中文或英文名称]。
先给出正式定义、前置知识和相关标准。
解释工作机制、输入输出、适用条件和边界。
用真实协议字段、代码或系统行为举例。
区分容易混淆的概念，给出可复现的最小实验。
最后提供知识检验及参考资料，注明未确认信息。
```

## 三、仓库变更（第 12、18 章）

```text
仓库及基准分支：
目标行为和当前问题：
允许修改的范围及必须保留的接口：
验收用例：
先检查工作区、运行时和依赖。
实现后执行相关测试与构建，报告实际结果和变更差异。
不要覆盖现有未提交修改、强制推送或擅自发布。
```

## 四、故障定位（第 9、14、23 章）

```text
环境、版本与影响范围：
复现步骤：
预期行为：
实际行为：
相关错误日志（已脱敏）：
最近变更及已尝试操作：
请按系统层次提出可验证假设，收集证据后定位根因。
修复后执行回归测试，明确尚未验证的范围。
```

## 五、性能分析（第 6、16 章）

```text
当前性能基线：
输入规模、并发与环境：
目标延迟、吞吐量和资源预算：
请使用 profiling、查询计划或测量结果定位瓶颈。
在相同工作负载下比较优化前后结果。
不得为提高性能移除必要的校验、权限或数据约束。
```

## 六、构建与部署（第 13、18 章）

```text
项目类型、仓库、目标版本：
目标环境与授权范围：
构建命令、产物目录及依赖版本：
配置和凭据注入方式（仅字段名）：
健康检查、业务验收、回滚及数据库迁移要求：
请先在测试环境执行构建与验证。
报告版本标识、实际检查结果及未解决风险。
生产变更必须在明确授权范围内进行。
```

## 七、安全与隐私（第 15、19—21 章）

```text
测试范围：仅限自有或明确授权的隔离环境。
资产、数据流、身份与权限矩阵：
已知敏感数据类型：
请审查服务端访问控制、输入输出处理、依赖、凭据及日志。
使用虚构数据执行正向和负向测试。
仅输出脱敏证据、影响和建议，不读取无关秘密。
```

## 八、数据库与恢复（第 17 章）

```text
数据存储位置及数据模型：
备份策略、RPO、RTO：
迁移目标及兼容性约束：
请验证备份能在隔离环境恢复。
检查数据完整性、约束、附件及业务查询。
报告实际恢复耗时及未覆盖数据。
禁止覆盖生产数据或未经授权执行迁移。
```

## 九、成本与维护（第 16、23 章）

```text
服务清单、用量、计费单位及价格来源：
正常、峰值和异常场景：
服务目标及维护责任人：
请估算各场景成本，区分硬限制和告警。
设计监控、维护计划与退出方案。
未经授权不得购买资源或修改生产配置。
```

## 十、交付复核（全书）

```text
交付范围及验收标准：
请提供实际修改的文件、Commit、测试和构建结果。
区分已完成、未完成、未验证及阻塞项。
列出关键假设、风险及复现命令。
不要将计划、推测或生成的文字标为已执行。
```

## 使用原则

任务拆分依据依赖与风险，而不是机械地限制每次只能修改一个文件。上下文中应保留最新需求及项目状态，重要决策写入仓库。高影响操作须遵守权限边界，最终交付以可独立复核的证据为准。
