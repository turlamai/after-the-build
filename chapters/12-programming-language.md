# 为什么我们不直接编写机器指令

前面我们已经知道，处理器可以执行一系列以数字编码的机器指令。假设要计算报名活动的剩余名额，我们需要让处理器取得总名额、取得已报名人数、执行减法，并保存结果。

可是，假如计算规则稍微复杂一点，我们就需要编写许多条指令，还要记住数据存放在哪里。更困难的是，更换处理器后，指令的编码方式可能也随之改变。

人能不能使用一种更便于阅读的文字描述计算过程，再由计算机负责将它转换为可以执行的操作？

这就是编程语言要解决的基本问题。

## 先给操作起一个名字

机器指令本质上是一组二进制数据。但我们可以为每种操作规定便于人阅读的名称。例如，在第二部介绍的教学处理器中，我们使用了 LOAD、ADD 和 STORE。

工程师可以使用这种符号形式编写指令，再用专门的程序将符号转换为相应的机器编码。这样的语言称为汇编语言（Assembly Language），负责转换的程序称为汇编器（Assembler）。

汇编语言使人不必逐条手写二进制编码，却仍然需要关心处理器提供的寄存器、存储器访问方法和指令。它与具体的指令集架构关系密切。

## 同一个计算在两种语言中的区别

沿用第二部的教学机器，地址 100 保存 3，地址 101 保存 5。汇编程序使用 LOAD 将数据放入寄存器，再执行 ADD 和 STORE。每条指令指定机器能够直接完成的操作。

高级语言则可以直接表达 result = 3 + 5。负责转换或执行这段代码的软件，需要保证计算结果符合语言规定。它不必严格生成我们手写的那四条指令：如果结果在转换时就能确定，甚至可以直接生成保存常量 8 的代码。

这种在保持规定行为的前提下改变实现方式的技术称为优化（Optimization）。因此，源代码与机器指令之间不一定存在逐行对应关系。

## 把注意力转移到我们想解决的问题

我们可以进一步规定一种表达方式：total 表示总名额，registered 表示已经报名的人数，而 remaining = total - registered 表示计算并记录剩余名额。

这样，我们关注的是业务数据及其关系，而不是数据究竟存放在哪个寄存器中。

以 Python 语言为例：

```python
total = 20
registered = 17
remaining = total - registered
print(remaining)
```

这四行文字可以表达一个完整的小任务，预期输出为 3。现在不要求你安装 Python，也不要求背诵这四行。我们先理解，人类能够用约定好的文字描述计算规则，而负责执行这些规则的软件可以处理更具体的机器操作。

比汇编语言更远离具体机器指令、提供更高层次表达能力的语言，通常称为高级编程语言（High-level Programming Language）。

这里的「高级」不是指它永远更快，也不是指它在所有任务上都更好，而是指它能够让我们在更高的抽象层次表达问题。

## 文字为什么不能随便写

如果把减法写成「帮我算一下还剩多少」，一般的 Python 实现并不能直接执行。原因在于编程语言需要有确定的表达规则。

语言对合法书写形式的规定称为语法（Syntax）；对合法表达所代表行为的规定称为语义（Semantics）。

例如 remaining = total - registered 是符合 Python 语法的语句。如果把减号写成加号，它仍然可能符合语法，但计算结果就与我们想要的业务规则不同。

因此，写出计算机能够接受的代码，与写出正确解决问题的代码，是不同的事情。这一点即使在 AI 能够自动生成代码之后也不会改变。
