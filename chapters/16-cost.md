# 第 16 章 技术成本：资源计量、容量规划与预算控制

> 先建立使用量与价格之间的模型，再决定架构和资源配置。

## 一、成本由什么组成

软件服务的总拥有成本（Total Cost of Ownership，TCO）包含开发、部署、运行、维护、迁移及故障处理等支出。云账单通常只覆盖其中部分资源费用。

| 资源 | 常见计量维度 |
|---|---|
| 计算 | vCPU 时间、内存时间、实例运行时间 |
| 存储 | 容量乘以时间、读写请求、备份 |
| 网络 | 出站传输量、请求数量、网络服务 |
| AI 推理 | 输入与输出 Token、请求或其他模型计量单位 |
| 托管服务 | 套餐、席位、数据库资源、最低消费 |

实际计费规则因服务而异，可能存在阶梯价格、最低计费单位、税费和区域差异。免费额度也可能是限时活动、固定配额或特定用途限制。

## 二、建立可计算的成本模型

假设一个测试应用每天处理 1000 次请求，每月按 30 天计算，共 30000 次。若每次 AI 调用平均使用 2000 输入 Token 和 500 输出 Token，则每月输入为 6000 万 Token，输出为 1500 万 Token。

假设输入价格为每百万 Token 1 元、输出价格为每百万 Token 4 元，则推理费用为：

60 × 1 + 15 × 4 = 120 元。

这些数字仅用于说明计算方法，不代表任何实际厂商报价。真实价格需要查阅指定模型和计费套餐，并考虑缓存、推理 Token、工具调用、失败重试以及税费等因素。

若 Agent 完成一次业务操作需要多次模型调用，应计算整个工作流的总用量，而不是只计算最终回答。

## 三、容量、性能与成本

容量规划（Capacity Planning）根据访问量、并发、数据增长和性能目标确定资源需求。资源利用率过低可能浪费费用，长期过高则可能引发排队、超时或故障。

缓存可以降低重复计算；批处理（Batch Processing）可以减少调用开销；分页和索引可以降低数据库及传输成本。但每种优化都应验证正确性、安全性和服务质量。

水平扩展会增加实例数量，因此应结合请求量、每实例处理能力及扩缩容延迟评估费用。自动扩缩容并不自动保证最低成本。

## 四、预算告警与硬限制

预算（Budget）定义目标支出，预算告警（Budget Alert）在满足阈值条件时通知用户。硬配额（Hard Quota）在限制生效时拒绝额外使用。限流控制单位时间请求数量，也可能降低异常消耗。

不能假设所有平台都有硬费用上限，也不能把预付费、银行卡余额或告警当作绝对的费用控制。计费延迟、关联资源和合同条款都可能影响最终应付金额。

应结合供应商支持的机制设置项目级配额、并发限制、单次请求最大输出、最大重试次数和异常告警。限制生效后的用户体验也需要设计，例如返回可理解的错误，而不是无限重试。

## 五、实践：建立预算表

为一个虚构应用记录每日活跃用户、每用户请求数、平均输入输出 Token、存储增量和出站流量。分别计算正常场景、峰值场景和异常循环场景。

为每项计费注明单位、价格来源及查询日期。将请求量扩大十倍、增加失败重试后重新计算，并比较限流与缓存策略的影响。练习可在本地表格完成，无需开通付费资源。

## 七、知识检验

- 为什么 Token 数不等于字符数？
- 为什么预算告警不等于支出上限？
- 如何估算 Agent 多轮工具调用的成本？
- 降低延迟是否必然降低总成本？
