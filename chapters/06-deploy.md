# 第 6 章 上线：把 localhost 变成一个真正的网址

> 部署听起来像专业术语，本质就一句话：把程序从你的电脑，搬进全世界都能敲门的服务器，再给它一个好记的地址。

## 一、翻车现场

序章的案子现在正式开庭。我太太的网页需要让朋友打开，解决办法只有一个：上线。她打开 AI 生成的项目，里面有个说明文件写着两条命令，还有英文单词 deploy（部署）。她盯着那两行字不敢动手——上一个她敢直接跑的东西还是微波炉。

另一个常见现场：搜索「怎么把网页给别人看」，出来十种方案、二十个平台、五十篇互相矛盾的教程，每一篇都默认你已经有某方面的背景知识。你收藏了五篇，一篇都没读完。

## 二、为什么会这样

### 部署的两半

把「上线」拆开，是两个动作。第一半，搬家：把程序连同它的家当，从你的电脑复制到一台二十四小时开机、有公网门牌号的服务器上。第二半，上牌：给这台服务器上的程序一个稳定、好记的地址，比如 myapp.example.com。

序章的问题出在第二半都没有。程序住在你电脑里，地址又是 localhost 这个自言自语的门牌号——两头都不通向「别人能访问」。

### 托管平台：把专业活变成几次点击

十年前，部署是专业运维的活：租服务器、装系统、配防火墙，每一步都能出错。现在有一类服务叫托管平台（如 Vercel、Netlify、Cloudflare Pages 这类），它们把整套专业操作封装起来：你把项目交出去，点几次按钮，它替你完成搬家、上牌、续命（自动重启、自动加密）。

它的商业模式也顺手讲清：免费档限制流量和功能，用的人多了或要求高了再付费。对你早期能造的东西，免费档通常绰绰有余。平台不是慈善，但你的规模确实在它的免单线以下，这是双赢。

### 域名：要不要买

托管平台会免费送你一个地址，形如 yourapp.vercel.app，能用，难记，且明示了平台归属。域名就是自己买一个名字（一年几十到几百块），指到你的东西上。什么时候值得买：要长期维护、要给正式的场合用、或者就是想要一个属于自己的门牌。买域名本身在哪个平台买都行（阿里云、腾讯云、Cloudflare 等），记好两件事：续费日期，和「域名是租的，不是买的」——不续费就回收。

## 三、怎么办

三条路线，按你现在的阶段排序。第一，纯网页（没有登录、没有数据库），用一键托管平台，免费、最快。第二，带后端逻辑的（要存用户数据、要登录），用带后端的一体化平台（Replit、Railway 这类），配置多一点但还在「点击」的范畴。第三，传统云服务商（阿里云、AWS），是给专业团队的，现阶段绕行——不是说不好，是它把所有自由度和所有责任一起交给你，你还没有需要它的那个规模。

通用五步，任何托管平台都长这样。第一步，连仓库：把项目代码放到 GitHub 这类代码仓库里（下一节讲为什么绕不开它）。第二步，选项目：在托管平台导入这个仓库。第三步，给钥匙：如果项目用到了密钥（第 8 章），把它们填进平台的设置里。第四步，点部署：等它搬完家，会给你一个网址。第五步，全流程试一遍：用你从没登录过的浏览器（或无痕模式）访问，把每个功能点一遍。

GitHub 这一步为什么绕不开：托管平台需要能随时拿到你的最新代码，仓库（GitHub）就是那个「代码的家」，平台监听它，你一更新它就自动重新部署。这也是你第一次真正用上「版本控制」这个概念，第 11 章展开。

上线不是终点，是第一次真正的验收。用陌生浏览器走完全流程，等于第一次站在「别人」的位置看你的东西——很多只在你电脑上成立的事，会在这时现形。

## 四、带走的问题

- 我的东西有没有后端（存数据、登录）？属于哪条路线？
- 我的代码在 GitHub 上吗？仓库地址是什么？
- 我的项目需要哪些钥匙？填到平台的哪里了？
- 部署完拿到的网址是什么？我收藏了吗？
- 我用无痕模式完整试过一遍吗？
- 我的域名（如果买了）什么时候续费？
