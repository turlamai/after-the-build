# 怎样把需求变成可以运行的结构

我们不需要为一个只有 20 个名额的教学应用引入许多独立服务。先采用一个浏览器、一项 Python 后端服务和一个 SQLite 数据库文件。

![报名教学项目的组成](../assets/intro-product-architecture.svg)

## 为什么这样选择

浏览器使用 HTML、CSS 和 JavaScript 显示界面并提交 HTTP 请求。Python 标准库提供本地 HTTP 实验服务；SQLite 提供结构化数据保存、查询和事务。

这样可以将安装要求限制为 Python 3，不需要额外的前端构建工具和数据库服务器。

这一选择只适用于本机教学范围，不表示 Python 自带的 HTTP 服务适合公网生产部署。

## 确定接口约定

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | / | 返回报名页面 |
| GET | /api/status | 返回容量与人数 |
| POST | /api/registrations | 提交姓名及请求标识 |

查询返回 JSON 对象，包含 capacity、registered 和 remaining。提交成功返回记录编号以及是否为重复请求；容量不足返回 409，并提供明确的错误字段。

服务端负责验证请求内容，不依赖浏览器表单的检查。SQLite 负责保存记录，并通过事务约束并发写入。

## HTTP 接口也是一个契约

| 状态码 | 本项目约定 |
|---:|---|
| 200 | 查询成功，或返回同一请求的已有报名结果 |
| 201 | 新记录已创建 |
| 400 | 请求体、姓名或请求标识不符合要求 |
| 404 | 不存在的接口路径 |
| 409 | 容量已满或请求标识冲突 |
| 415 | 不支持的请求内容类型 |
| 503 | 数据库操作暂时不可用 |

服务端只接受 JSON 对象形式的报名请求，并限制请求体大小。错误响应提供具体错误字段，前端不应将所有失败都理解为没有名额。

这个设计只解决有限的本地教学需求。它没有实现生产级 HTTP 服务器所需的完整请求生命周期限制，也没有认证及授权机制。不要将其作为公网服务模板直接部署。

## 数据库结构

报名表包含整数主键、唯一请求标识及姓名。总名额作为服务端的固定业务规则。

每次尝试报名时，在一个写事务内先检查请求标识，再检查当前记录数，最后在允许的情况下插入记录。

SQLite 的 BEGIN IMMEDIATE 在此实现中用于取得写事务，避免两个写入者同时依据同一份旧人数作出决定。其他数据库的并发方案需要根据自身事务机制设计。
