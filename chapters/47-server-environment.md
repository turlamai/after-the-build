# 为什么自己电脑上的程序还需要部署

第 39 章中，我们启动了一个只能从本机访问的 HTTP 服务。第六部又建立了保存报名记录的数据库。如果希望其他人每天都能通过网络报名，我们还需要为这些程序准备一个持续工作的环境。

## 服务器首先是一种角色

客户端发出请求，服务端处理请求。能够运行服务端程序的计算机，可以承担服务器（Server）的角色。普通电脑也可以提供服务。但长期运行的设备需要考虑供电、网络连接、故障、性能和维护条件。专用服务器硬件可能提供冗余电源、更多内存以及远程管理能力。

服务器也可以指提供服务的软件。例如 HTTP 服务器负责处理 HTTP 请求。阅读技术文档时，要判断它指的是机器还是程序。

## 将程序复制过去就能运行吗

假设我们将报名后端复制到一台安装 Linux 的机器。根据第四部的知识，需要确认处理器架构、操作系统、依赖、运行时、数据库地址、文件权限、监听地址和端口。

这些条件共同构成应用的运行环境（Execution Environment）。部署（Deployment）不仅是复制文件，而是使程序及相关资源在目标环境中能够按要求工作。

## 如何持续运行程序

如果从终端启动后端，关闭终端后程序是否继续运行，取决于进程的启动与管理方式。正式服务一般由系统的服务管理机制负责。例如，许多 Linux 系统采用 systemd 启动服务、记录状态，并根据配置在故障后重启。

自动重启并不等于修复故障。如果数据库配置错误，反复重启只会重复错误。程序还需要提供运行记录，并使管理员能够观察和诊断状态。

## 服务运行状态与进程运行状态不同

一个进程已经启动，不代表它已经能够提供业务服务。例如报名后端可能正在建立数据库连接，或者已经监听端口，却无法读取数据。

可以把启动、就绪（Readiness）和存活（Liveness）分开理解：启动表示初始化过程正在进行或已经完成；就绪表示当前可以接收业务请求；存活检查则尝试判断程序是否需要恢复或重启。具体检查方式取决于部署平台。

如果数据库暂时不可用，后端可能应当停止接收新请求，而不是被不断重启。服务管理器还应限制重启频率，保留有助于定位问题的记录。

服务停止时，也可以先停止接收新请求，再处理已经开始的工作，最后释放资源。这种有序停止的方式常称为优雅退出（Graceful Shutdown）。它需要合理的等待上限，且不能保证所有异常断电都能够有序完成。

## 后端与数据库一定要分开吗

报名后端和数据库可以在同一台机器运行，也可以分别部署。应用通过数据库接口访问数据，并不要求数据库必须独占一台机器。

分开部署可能有利于独立分配资源，但也会增加网络延迟、连接失败以及管理复杂度。小型应用通常应当从能够满足业务要求的简单方案开始。
