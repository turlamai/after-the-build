# 从一个比特到一份数据

我们已经知道，一个二进制位可以表示 0 或 1，多个位置组合后可以表示更大的数。实际计算机里有许多这样的位。如果每次都单独描述每一位，表达起来并不方便。

现代计算机通常把八个比特组织成一个基本单位，叫作字节（Byte）。

八个比特共有 256 种组合。如果把它们解释成不带负号的整数，就可以表示 0 到 255。这种解释叫无符号整数（Unsigned Integer）。

## 为什么需要十六进制

一个字节的二进制表示可能是 11111111。连续写许多字节时，二进制字符串会很长，容易数错位置。工程师常用十六进制（Hexadecimal）简洁地展示这些数据。

十六进制需要十六种数字符号，除了 0 到 9，再用 A、B、C、D、E、F 表示十到十五。

四个二进制位恰好有十六种组合，因此每四个二进制位都可以用一个十六进制数字表示。

| 二进制 | 十六进制 | 十进制 |
|---|---|---:|
| 0000 | 0 | 0 |
| 1001 | 9 | 9 |
| 1010 | A | 10 |
| 1111 | F | 15 |

例如 11111111 可以拆成 1111 和 1111，写成 FF。常用前缀 0x 表示后面的数字采用十六进制，因此 0xFF 就是十进制的 255。

十六进制不是另一种物理存储方式，而是人们查看同一组数据时采用的记法。以后看到文件内容、网络数据和设备调试信息里的一串十六进制数字，就不必感到陌生。

## 为什么一个字节不能表示所有数字

一个字节表示无符号整数时最多到 255。如果需要表示 256，可以使用更多的位。两个字节共有 16 位，可以表示 0 到 65535；四个字节共有 32 位，可以表示更大的数。

实际应用还需要负数、小数等。它们有各自的表示规则，不能简单地把任何二进制序列都解释成无符号整数。下面就来研究这些表示。

## 怎样表示负数

现在规定只使用八个位。我们可以拿出一部分组合表示负数，但必须首先确定规则。现代计算机表示固定宽度的有符号整数时，广泛使用二进制补码（Two's Complement）。

八位补码的最左边一位权重为 -128，其余七个位权重仍为 64、32、16、8、4、2、1。因此：

| 八位表示 | 补码整数 | 无符号整数 |
|---|---:|---:|
| 00000000 | 0 | 0 |
| 00000101 | 5 | 5 |
| 01111111 | 127 | 127 |
| 10000000 | -128 | 128 |
| 11111011 | -5 | 251 |
| 11111111 | -1 | 255 |

例如 11111011 的补码数值是 -128 + 64 + 32 + 16 + 8 + 2 + 1 = -5。同样的位组合，使用不同规则解释，会得到不同数值。

![八位补码的每一位权重](../assets/intro-twos-complement.svg)

一种得到负数补码的方法是：先写出相应正数的固定宽度二进制表示，将每个位的 0 与 1 互换，再加 1，保留规定宽度内的位。5 的表示为 00000101，反转得到 11111010，再加 1 得到 11111011。

八位补码的范围是 -128 到 127。它不需要为正零和负零分别保留一种组合。

## 计算结果超出范围怎么办

如果八位无符号整数 255 加 1，数学结果是 256，需要九个位表示。如果只保留低八位，就得到 00000000。这叫回绕（Wraparound）。

如果以八位补码解释 01111111，再加 1 并只保留八位，就得到 10000000，解释为 -128，而不是数学结果 128。

当数学结果超出所选数值表示的范围时，称为溢出（Overflow）。实际编程语言和运算环境可能采取不同处理方式：回绕、报告错误、使用更宽的表示，或者对某些运算不保证结果。不能认为所有语言都会自动回绕。

## 小数又怎样表示

十进制的小数点右侧每一位的权重是前一位的十分之一。二进制小数点右侧则依次是 1/2、1/4、1/8 等。例如二进制 10.101 等于 2 + 1/2 + 1/8，也就是十进制的 2.625。

可以事先约定小数点位置，这称为定点表示（Fixed-point）。但如果希望同一种表示既容纳非常小的数，也容纳非常大的数，就可以采用类似科学计数法的结构。

例如十进制的 6250 可以表示为 6.25 × 10³。二进制的 10.101 可以表示为 1.0101 × 2¹。这种将有效数字与指数分开保存的思想称为浮点表示（Floating-point）。

常见 IEEE 754 单精度二进制浮点格式使用 32 位：1 位符号、8 位指数编码、23 位小数部分。对于普通规格化的有限非零数，有效数字还包含一个未直接保存的前导 1。特殊编码另有零、非规格化数、无穷大和非数值（NaN）等规则。

![单精度浮点数的字段与普通规格化数值](../assets/intro-float-fields.svg)

由于有限的二进制位不能精确表示所有小数，十进制 0.1 在常见二进制浮点格式中只能近似保存。连续计算也可能积累误差。涉及金额时，常采用整数最小货币单位或适当的十进制定点表示，并规定舍入规则。

现在不必记住完整的 IEEE 754 公式。重要的是理解：数值的表示范围、精度与运算规则，取决于所选择的格式。后续编程时会用到这一事实。

## 为什么文件大小有时看起来不一样

当我们保存大量数据时，就需要用更大的单位计量字节数。

按照十进制单位，1 kB 等于 1000 字节，1 MB 等于 1000000 字节，1 GB 等于 1000000000 字节。按照二进制单位，1 KiB 等于 1024 字节，1 MiB 等于 1048576 字节，1 GiB 等于 1073741824 字节。

一些软件历史上使用 KB、MB、GB 标签展示按 1024 计算的结果。因此比较容量时，应确认单位实际采用的规则。

另外，比特和字节不能混为一谈。通信速率常以每秒多少比特表示，而文件容量常以字节表示。忽略这一差异，会让传输速度的估算出现八倍的偏差。

## 字节只是表示，含义取决于规则

现在看一个字节 0x41。如果把它当成无符号整数，它表示 65。但按照一种文字编码，它也可以表示大写字母 A。

这正是第一章的思想：数据的含义需要由解释规则来决定。
