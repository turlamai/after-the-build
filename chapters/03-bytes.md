# 从一个比特到一份数据

我们已经知道，一个二进制位可以表示 0 或 1，多个位置组合后可以表示更大的数。实际计算机里有许多这样的位。如果每次都单独描述每一位，表达起来并不方便。

现代计算机通常把八个比特组织成一个基本单位，叫作字节（Byte）。

八个比特共有 256 种组合。如果把它们解释成不带负号的整数，就可以表示 0 到 255。这种解释叫无符号整数（Unsigned Integer）。

## 为什么需要十六进制

一个字节的二进制表示可能是 11111111。连续写许多字节时，二进制字符串会很长，容易数错位置。工程师常用十六进制（Hexadecimal）简洁地展示这些数据。

十六进制需要十六种数字符号，除了 0 到 9，再用 A、B、C、D、E、F 表示十到十五。

四个二进制位恰好有十六种组合，因此每四个二进制位都可以用一个十六进制数字表示。

| 二进制 | 十六进制 | 十进制 |
|---|---|---:|
| 0000 | 0 | 0 |
| 1001 | 9 | 9 |
| 1010 | A | 10 |
| 1111 | F | 15 |

例如 11111111 可以拆成 1111 和 1111，写成 FF。常用前缀 0x 表示后面的数字采用十六进制，因此 0xFF 就是十进制的 255。

十六进制不是另一种物理存储方式，而是人们查看同一组数据时采用的记法。以后看到文件内容、网络数据和设备调试信息里的一串十六进制数字，就不必感到陌生。

## 为什么一个字节不能表示所有数字

一个字节表示无符号整数时最多到 255。如果需要表示 256，可以使用更多的位。两个字节共有 16 位，可以表示 0 到 65535；四个字节共有 32 位，可以表示更大的数。

实际应用还需要负数、小数等。它们有各自的表示规则，不能简单地把任何二进制序列都解释成无符号整数。我们将在后面专门研究。

## 为什么文件大小有时看起来不一样

当我们保存大量数据时，就需要用更大的单位计量字节数。

按照十进制单位，1 kB 等于 1000 字节，1 MB 等于 1000000 字节，1 GB 等于 1000000000 字节。按照二进制单位，1 KiB 等于 1024 字节，1 MiB 等于 1048576 字节，1 GiB 等于 1073741824 字节。

一些软件历史上使用 KB、MB、GB 标签展示按 1024 计算的结果。因此比较容量时，应确认单位实际采用的规则。

另外，比特和字节不能混为一谈。通信速率常以每秒多少比特表示，而文件容量常以字节表示。忽略这一差异，会让传输速度的估算出现八倍的偏差。

## 字节只是表示，含义取决于规则

现在看一个字节 0x41。如果把它当成无符号整数，它表示 65。但按照一种文字编码，它也可以表示大写字母 A。

这正是第一章的思想：数据的含义需要由解释规则来决定。
