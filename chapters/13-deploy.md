# 第 13 章 软件部署：从构建产物到生产服务

> 部署不是复制代码，而是将特定版本的产物、配置和运行环境组合成可访问、可验证、可恢复的服务。

## 一、开发环境与生产环境

开发环境（Development Environment）用于编写和调试代码，测试环境（Test Environment）用于验证行为，预发布环境（Staging Environment）尽量模拟生产条件，生产环境（Production Environment）承担真实用户请求。环境的区别主要在配置、数据、权限和运行目标，而不是目录名称。

例如报名系统在开发环境使用本地测试数据库，在生产环境使用独立数据库和正式凭据。将开发数据库直接暴露给公网，或将真实用户数据复制到不受保护的测试环境，都会引入风险。

构建（Build）产生可交付文件，发布（Release）标识可分发版本，部署（Deployment）使某个版本进入目标环境并运行。发布版本不一定已经部署，部署成功也不意味着功能正确。

## 二、选择与架构相符的部署方式

| 系统形态 | 部署对象 | 需要确认 |
|---|---|---|
| 静态站点 | HTML、CSS、JavaScript、图片 | 构建目录、资源路径、缓存 |
| Web 后端 | 服务进程或容器 | 运行时、端口、健康检查、配置 |
| 数据库应用 | 应用与持久化数据库 | 数据库连接、迁移、备份 |
| 桌面应用 | 针对平台的安装包 | 架构、签名、更新机制 |

静态托管无需为每次请求运行独立业务进程，但浏览器仍可能通过 API 访问其他服务。涉及私密凭据、业务权限或数据库写入时，应判断这些逻辑是否需要服务端实现。

托管平台可以从 Git 仓库获取源码，也可以接收已构建产物或容器镜像。GitHub 不是部署的必需条件。使用任何平台前应核对构建命令、输出目录、支持的运行时版本和实际责任分界。

## 三、持续集成和部署流水线

持续集成（Continuous Integration，CI）是在代码变更后自动执行构建、检查及测试。持续交付（Continuous Delivery）使通过验证的版本保持可发布状态；持续部署（Continuous Deployment）进一步自动将符合条件的变更部署至目标环境。

典型流水线包括：

1. 获取指定 Git Commit，按锁定文件安装依赖。
2. 执行静态检查、测试和构建。
3. 为产物记录版本及完整性信息。
4. 部署至测试环境并执行健康检查、端到端测试。
5. 按授权和发布策略部署生产环境，持续观察错误率与延迟。

流水线本身也需要最小权限。来自不受信任分支的构建任务不应自动获得生产凭据。

## 四、网络入口与配置

后端服务通常监听某个地址和端口。反向代理可以接收公网 HTTPS 请求，再转发至内部服务。DNS 将域名解析到目标地址或别名，TLS 证书用于验证目标服务身份并建立安全连接。

服务在本机能够访问不等于公网可达。应检查监听地址、防火墙、路由、代理配置与域名解析。公开服务之前先确认认证、授权和数据暴露范围。

配置（Configuration）决定应用在环境中的具体行为，例如数据库地址、日志级别和允许访问的来源。凭据应通过受控配置注入；前端构建产物中不得包含仅供服务端使用的秘密。

## 五、健康检查与回滚

健康检查（Health Check）用于判断实例是否存活或具备接收请求的条件。进程存在、端口可连接、健康接口返回正常是不同层次的证据；关键业务还需要功能测试。

滚动发布（Rolling Deployment）逐步替换实例，蓝绿部署（Blue-green Deployment）通过两套环境切换流量，灰度发布（Canary Deployment）先让小部分流量进入新版本。是否采用这些机制取决于系统规模与风险。

回滚（Rollback）恢复已知可用版本，但数据库结构和外部状态可能已经改变。数据库迁移应考虑向后兼容、备份及恢复演练，不能只依赖重新部署旧代码。

## 六、实践：验证静态站点部署

选择仅包含公开测试内容的静态项目，检查 README 中的构建命令与输出目录。若为 Node.js 项目且存在适用锁定文件，按项目文档安装依赖并执行构建；不要对不可信项目直接运行安装脚本。

在本地预览构建目录，检查入口页面、子路径、资源加载、刷新行为和浏览器控制台。部署后使用另一网络环境或未登录浏览器验证公开访问，再核对实际运行版本是否对应预期提交。无需为练习购买域名。

## 七、与 Agent 协作

请识别项目类型、构建入口、产物目录和运行时版本；建立 CI，在测试环境验证关键页面与 API。检查生产配置是否泄露凭据、是否需要数据库迁移、能否回滚。输出部署版本、验证证据和未解决风险，未经授权不修改生产域名或数据库。

## 八、知识检验

- CI、持续交付、持续部署有何区别？
- 为什么构建成功不代表部署成功？
- 为什么数据库迁移可能使代码回滚失效？
- 静态托管是否意味着浏览器不会访问后端？

进阶方向：不可变产物、GitOps、基础设施即代码、供应链证明与零停机迁移。
