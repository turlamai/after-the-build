# 文件能够保存字节，为什么还需要数据格式

我们的报名程序现在能够接收来自不同设备的请求。但如果程序停止运行后，报名信息全部消失，它就不能承担真正的业务。

第十九章已经讲过，普通文件可以保存一组字节。我们现在要解决的问题是：怎样让程序在下一次启动时，正确地理解以前保存的字节？

## 从一条报名记录开始

假设有一位申请者叫小林，报名编号为 17。

我们可以把编号和姓名写在一行：

```text
17,小林
```

如果约定逗号之前是编号，之后是姓名，那么另一个程序读到这一行，也可以按照约定恢复这两个值。

将多个报名者的信息放在一起：

```csv
id,name
17,小林
18,小王
19,小陈
```

第一行规定了各列的名称，其余每行保存一条记录。这是 CSV（Comma-Separated Values，逗号分隔值）的一种常见形式。

CSV 的具体规则还需要考虑字段中出现逗号、引号或者换行的情况。例如一个包含逗号的字段可以用双引号包围。不能简单地把任何逗号都当成字段边界。

## 字符编码和文件格式解决不同的问题

UTF-8 规定怎样将字符编码为字节。CSV 则进一步规定这些字符怎样组成字段和记录。

知道文件采用 UTF-8，只能帮助我们恢复文字；知道它采用 CSV，才能进一步解释记录的结构。

这正是为什么一个文件可能能够正常显示文字，却仍然无法被某个应用正确导入。

## 为什么不能直接按照逗号拆分每一行

假设报名记录中的姓名字段允许出现逗号。CSV 可以通过引号明确一个字段的边界。字段本身包含双引号时，常见 CSV 规则使用两个连续双引号表示一个双引号。

下面使用 Python 标准库解析一段内存中的 CSV 文本，不需要创建文件：

```python
import csv
import io

source = 'id,name\n17,"Lin, Alice"\n18,"王""小明"\n'
records = list(csv.DictReader(io.StringIO(source)))
assert records[0]["name"] == "Lin, Alice"
assert records[1]["name"] == '王"小明'
assert records[0]["id"] == "17"
```

DictReader 使用第一行的列名组织记录。请注意，编号 17 在这个例子中仍然是字符串，而不是整数。程序应根据业务规则进行类型转换及验证。

这一实验说明：解析器必须按照格式规则识别边界；恢复字段之后，还需要决定每个字段的含义。CSV 的不同实现可能使用不同分隔符或引号规则，交换数据前应该确认相应约定。

## 格式并不是所有数据的统一答案

对于图片，文件中需要表达图像尺寸、颜色和像素相关信息。对于音频，则需要表达采样和声音数据。每种格式都有自己的结构规则。

有些格式采用便于人阅读的文本表示，有些采用更紧凑或适合特定处理方式的二进制表示。

文件扩展名可以提示使用什么格式，却不能保证内容确实满足相应规范。
