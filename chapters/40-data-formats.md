# 文件能够保存字节，为什么还需要数据格式

我们的报名程序现在能够接收来自不同设备的请求。但如果程序停止运行后，报名信息全部消失，它就不能承担真正的业务。

第十九章已经讲过，普通文件可以保存一组字节。我们现在要解决的问题是：怎样让程序在下一次启动时，正确地理解以前保存的字节？

## 从一条报名记录开始

假设有一位申请者叫小林，报名编号为 17。

我们可以把编号和姓名写在一行：

```text
17,小林
```

如果约定逗号之前是编号，之后是姓名，那么另一个程序读到这一行，也可以按照约定恢复这两个值。

将多个报名者的信息放在一起：

```csv
id,name
17,小林
18,小王
19,小陈
```

第一行规定了各列的名称，其余每行保存一条记录。这是 CSV（Comma-Separated Values，逗号分隔值）的一种常见形式。

CSV 的具体规则还需要考虑字段中出现逗号、引号或者换行的情况。例如一个包含逗号的字段可以用双引号包围。不能简单地把任何逗号都当成字段边界。

## 字符编码和文件格式解决不同的问题

UTF-8 规定怎样将字符编码为字节。CSV 则进一步规定这些字符怎样组成字段和记录。

知道文件采用 UTF-8，只能帮助我们恢复文字；知道它采用 CSV，才能进一步解释记录的结构。

这正是为什么一个文件可能能够正常显示文字，却仍然无法被某个应用正确导入。

## 格式并不是所有数据的统一答案

对于图片，文件中需要表达图像尺寸、颜色和像素相关信息。对于音频，则需要表达采样和声音数据。每种格式都有自己的结构规则。

有些格式采用便于人阅读的文本表示，有些采用更紧凑或适合特定处理方式的二进制表示。

文件扩展名可以提示使用什么格式，却不能保证内容确实满足相应规范。
