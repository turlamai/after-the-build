# 源代码怎样变成计算机可以执行的程序

我们已经用 Python 写过 total = 20 这样的语句。但处理器的指令集并没有规定如何识别这个单词。处理器能够直接执行的是符合其指令集架构的机器指令。

那么，一段以编程语言写成的文字怎样最终变成机器执行的操作？

## 写下来的代码是一种数据

以编程语言书写的原始程序文本称为源代码（Source Code）。源代码里的字母、数字和标点，可以像其他文字一样使用 UTF-8 等编码保存。

如果将这些字节直接交给 CPU，并要求它把每个字节当作机器指令执行，通常得不到我们想要的结果。

因此，必须有能够理解编程语言规则的软件。

## 先转换，再执行

一种办法是先阅读源代码，分析它表示的计算规则，然后生成另一种程序表示，例如面向某种处理器的机器代码。这种转换称为编译（Compilation），负责转换的程序叫编译器（Compiler）。

生成机器代码的过程中，还可能需要将不同部分的代码和已有功能组织起来。将相关代码及其引用关系组合、解析的过程称为链接（Linking）。

最终生成的文件可能是可以由操作系统装载并运行的可执行文件（Executable）。

注意，编译器的目标不一定是机器代码。它也可以将源代码转换成供另一套执行系统使用的中间表示。

## 一个可执行文件是怎样组成的

以常见的 C 语言工具链为例，程序可能由两个源文件组成：一个负责程序入口，另一个提供计算函数。

编译器可以分别将它们转换为目标文件（Object File）。目标文件可能包含机器代码、数据，以及尚待确定的引用。例如入口函数调用了另一个文件中定义的函数，但此时还没有确定那个函数最终放在哪里。

链接器（Linker）将需要的目标文件和库组合，解析这些引用，并根据目标格式安排代码和数据。若必要的定义不存在，链接就可能失败，即使每个源文件都已经成功编译。

静态链接可以将所需库代码的一部分纳入最终产物；动态链接则允许程序在装载时或运行期间使用独立提供的共享库。两者可以组合使用。

操作系统启动可执行文件时，还要按照文件格式建立运行环境并进入规定的程序入口。目标文件与最终可执行文件并不是同一种产物。

## 由另一个程序负责执行

另一种办法是让一个已经能够运行的程序读取我们写下的代码，根据语言规则实施相应的计算。这种按程序表示执行其行为的方式称为解释（Interpretation），承担这项工作的软件常称为解释器（Interpreter）。

例如常见的 CPython 实现通常先把 Python 源代码转换为内部字节码，再由执行系统处理这些字节码。这里的字节码（Bytecode）是一种面向特定执行系统的指令表示，不等于 CPU 的机器指令。

还有一些系统会在程序运行期间将部分代码转换为机器代码，这叫即时编译（Just-in-time Compilation，JIT）。

因此，不能简单认为某种编程语言天生只能编译或只能解释。不同实现可以组合多种方法。

## 为什么运行程序时还需要其他软件

程序执行时可能需要管理内存、创建字符串、处理错误或者调用已有功能。为程序提供这些支持的执行环境和相关机制，通常称为运行时（Runtime）。

不同程序依赖的运行时可能不同。有的程序把较多支持功能包含在发布产物中，有的要求目标设备事先安装相应软件。

因此，如果 AI 写好了一个 Python 程序，并不意味着任何电脑都可以立即运行。我们至少还要确认目标设备上存在合适的 Python 实现，或者采用一种包含必要运行支持的发布方式。

我们已经了解了一段源代码如何最终驱动处理器执行操作。不过，还有一个更早的问题：当电脑刚刚通电时，负责运行这些软件的第一个程序从哪里来？
