# 网站究竟被放在什么地方

假设现在准备让报名网站对外提供服务。注册域名、租用服务器、上传网页，这几件事情之间是什么关系？

## 域名并不负责运行程序

第五部已经解释，域名是按照一定规则管理的名称，DNS 可以提供该名称相关的地址记录。注册域名并不意味着同时拥有一台可以运行程序的计算机。

可以保留同一域名，将应用从一台服务器迁移到另一台，并按照部署方案调整 DNS 记录。

## 为什么有些网站不需要自己的后端

第 37 章写过一份 HTML 页面。服务器只需返回已经存在的文件，浏览器即可解析显示。这种主要分发事先生成的网页文件的方式称为静态网站托管（Static Site Hosting）。

文档、书籍和许多介绍性网站可以这样部署。作者不一定需要管理一个长期运行的自定义业务进程。

但报名系统必须根据最新记录判断名额，仅返回固定的 HTML 无法完成共享数据管理。动态服务需要在收到请求时执行相应的业务规则。

静态页面也可以运行 JavaScript 并访问动态服务。因此，静态托管描述的是内容交付方式，而不是页面没有交互能力。

## 托管服务提供什么

托管（Hosting）是借助相应的运行或分发环境，使应用或内容可以被访问。我们可以自行租用计算资源，也可以让专门的平台负责网页分发、程序运行或数据库管理。

![域名解析与托管运行环境的不同职责](../assets/intro-hosting-entry.svg)

正式服务还可能使用反向代理（Reverse Proxy）：公开入口接收客户端请求，再根据配置联系后面的业务进程。于是业务进程可以与对外连接管理分开。

反向代理不是天然的安全屏障，仍需要正确配置访问规则和授权。公开网站还应使用 HTTPS，具体保护机制将在密码学部分解释。

## 反向代理怎样连接不同服务

设公开入口为 https://registration.example.com。代理可以按照请求路径将 /api/ 开头的请求转给内部应用进程，将其他请求交给网页文件服务。

对于典型的 HTTP 反向代理，浏览器与代理建立一个连接，代理再建立或复用到上游（Upstream）的连接。浏览器不必知道业务进程实际监听的内部地址。

![公开入口与内部服务的请求路径](../assets/intro-proxy-upstreams.svg)

代理如果负责 HTTPS 连接的安全处理，需要明确代理与上游之间的连接是否也受到适当保护。代理转发客户端地址等信息时，上游还必须区分来自可信代理的信息与客户端自行填写的头部，不能无条件相信这些字段。

DNS 解析、代理路径匹配和上游业务执行各自可能失败。定位问题时，应当先判断请求是否真正到达了预期组件。
